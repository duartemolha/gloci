# gloci — Agent Usage Guide

<!-- Generated by: cargo xtask docs --skill SKILL.md -->

## Core semantics

- **0-based half-open coordinates:** Internally every feature is a 0-based, half-open interval `[start, end)` with 64-bit unsigned coordinates (BED is 0-based `[start, end)`; GFF/GTF is 1-based closed `[start, end]`; VCF/BCF is 1-based `POS`; CLI `--region` strings are 1-based inclusive `chr1:1,000-2,000`). Input format is auto-detected from content, never extensions (`--format`, `--a-format`, `--b-format` override; `-` reads stdin; `.gz` output is always BGZF; `-o FILE` writes atomically).
- **Points and overlap:** Zero-length features (`start == end`, e.g. BED insertion sites or pure VCF insertions) are points between bases. Non-empty intervals overlap when they share a base (`max(a.start, b.start) < min(a.end, b.end)`). A point overlaps an interval only when strictly inside it (`start < p < end`), or on either edge with `--inclusive-points`; two points overlap when equal. Every overlap threshold (`-f`, `-F`, `-r`, `-e`, `--min-bases`) counts as met when either side is a point.
- **VCF allele footprints:** By default (`--vcf-span allele`), a VCF/BCF record spans the reference bases its ALT alleles change after trimming shared REF/ALT prefixes and suffixes (a pure insertion is a point at `POS`; a deletion excludes its anchor base; multi-allelic records span the union of ALT footprints). Pass `--vcf-span ref` for `[POS-1, POS-1+len(REF))` (reproducing bedtools, tabix, and bcftools).
- **Lexicographic vs karyotype chromosome order:** Chromosome order priority is `-g` (built-in genome such as `hg38` or `GRCh38`, or `.fai`/`.genome`/`.dict`/BAM/VCF header) > the first input header that lists contigs (a VCF/BCF header's `##contig` lines, or an alignment header's `@SQ` lines) > `--chrom-order` (default `lex`: byte order `chr1, chr10 ... chr2`, as `bedtools sort`, `sort-bed` and `LC_ALL=C sort -k1,1`; `--chrom-order karyotype` gives `chr1, chr2 ... chr22, chrX, chrY, chrM`).
- **Sortedness errors and fixes:** Streaming commands (`intersect`, `subtract`, `closest`, `map`, `coverage`, `merge`, `complement`, `cluster`, `spacing`, `partition`, `genomecov`) verify `(chrom, start)` order on the fly and exit 1 on the first violation. Fix unsorted or karyotype-sorted inputs with one of:
  - `--sort`: externally sorts inputs first bounded by `--max-mem` (spilling to `--tmp-dir`).
  - `--unsorted` (`intersect`, `subtract`, `closest`, `map`, `coverage`): loads all `-b` files into memory and streams `-a` in its original order.
  - `--chrom-order karyotype`, or `-g GENOME`: accepts a file in karyotype order (from a VCF or BAM header, `gloci convert` of one, or `gloci sort --chrom-order karyotype`).
- **VCF passthrough vs TSV output:** Commands that emit A's records unchanged (`view`, `sort`, `intersect --mode any|none`, `subtract`, `vcf filter`) write A's format (VCF A keeps its header plus a `##glociCommand` line). Commands that append columns (`intersect --mode pairs|count`, `closest`, `map`, `coverage`) write TSV (VCF A gets a single `#CHROM\tPOS...` column-name line and no meta-header; BED/GFF A keep headers only with `--header`). `merge`, `complement`, `windows`, and `convert` write BED.

## Pitfalls

- **`--max-missing` is inverted from vcftools:** In `gloci vcf filter`, `--max-missing FRAC` is the *maximum fraction of missing genotypes* (`--max-missing 0.1` allows at most 10% missing, matching `bcftools view -i 'F_MISSING<=0.1'`). In `vcftools`, `--max-missing 0.9` meant at least 90% called. Translate `vcftools --max-missing X` to `gloci vcf filter --max-missing (1 - X)`.
- **`--vcf-span ref` reproduces bedtools, tabix, and bcftools:** gloci defaults to `--vcf-span allele` (trimmed ALT allele footprints; insertions are zero-length points, deletions exclude the anchor base). Pass `--vcf-span ref` when a pipeline expects `[POS-1, POS-1+len(REF))` spans (and add `--inclusive-points` when matching `tabix` or `bedtools` on edge insertions or zero-length BED records).
- **Karyotype-sorted files need `-g` or `--chrom-order karyotype`:** gloci's default chromosome order is byte order (`chr1, chr10, chr2`), as `bedtools sort`, `sort-bed` and `LC_ALL=C sort -k1,1 -k2,2n` write it. A file in karyotype order (`chr1, chr2 ... chrX`, as a VCF or BAM header lists it, or `gloci convert` of one) triggers a sortedness error. Pass `-g GENOME` or `--chrom-order karyotype` to accept it, `--sort` to re-sort on the fly, or `--unsorted` (on relation commands) to index `-b` in memory.
- **Filter expressions are a subset of bcftools `-i`/`-e`:** `gloci vcf filter --include/--exclude EXPR` (also on `vcf extract` and `vcf stats`) accepts fields against a number, string or `.`, `&&`, `||`, `!`, `INFO/KEY[i]`, `GT="het"` style keywords, `N_PASS(...)`, `MAF`, `AC`, `AN`, `F_MISSING`, `N_MISSING`, `TYPE`, and the FORMAT fields `GT`, `DP`, `GQ` only. Functions other than `N_PASS` (`ABS`, `STRLEN`, `MIN`, `MAX`, `SUM`, ...), other FORMAT fields (`FMT/AD`, `FMT/FT`, `FMT/PL`), field-against-field comparisons, arithmetic, the sample-wise `&` and `|`, and POSIX regex syntax are usage errors (exit 2). A bare `DP` that is both INFO and FORMAT must be written `INFO/DP` or `FMT/DP`. With `--samples`, the expression sees only the selected samples (bcftools sees all of them). gloci never sets FILTER (no `bcftools filter -s`): it removes records. `bcftools view -f PASS` is `--keep-filter PASS`, not `--pass-only` (which also keeps FILTER `.`).
- **`--chrom-map` renames on input, and `--assume-sorted` then means sorted by the new names:** `--chrom-map MAP` (two tab-separated columns, old and new; unlisted names are kept) makes order checks, `-g` and the output use the new names, and `-g` itself is never renamed. `gloci view --assume-sorted` trusts that the file is sorted by the new names. An order-reversing map is safe (it warns "could not locate ... scanning the whole file" and scans), but a map that renames onto a name already in the file (`a`→`c` in a file that also has `c`) can make it return a partial answer silently where the plain scan errors "not sorted". Rename and re-sort first: `gloci view FILE --chrom-map MAP | gloci sort - -o renamed.bed.gz --write-index`.
- **`-v` counts of an indexed BAM `-b` are of the reads read:** with `-t` above 1, an indexed `-b` (and anything under `--region`) is read only where A needs it, so the unmapped-reads-left-out counts depend on the thread count; the line says so. The counts for A are whole-file at every `-t`.
- **`vcf stats` checks FORMAT fields lazily:** a malformed DP, GQ or FT value that no requested statistic or mask rule reads is not an error.
- **CRAM needs the FASTA it was made with, and only through `--reference`:** `gloci view x.cram --reference ref.fa` (bedtools `--cram-ref`); `intersect`, `coverage`, `genomecov`, `convert`, `view` and `sort` all take `--reference` and read a CRAM (`sort` and `view` write BAM or SAM, never CRAM; `gloci index x.cram` takes it as an optional length check), and warn when it is given with no CRAM input. There is no `REF_PATH`, no reference cache and no download, so a CRAM samtools decodes through `REF_PATH` or the `UR:` path still needs `--reference` here. The FASTA needs its `.fai` (and `.gzi` when BGZF: `gloci index ref.fa.gz`), and its sequence lengths must equal the CRAM's `@SQ` lengths (else `was not made with`, before any record); a changed base in a slice's region is `does not match`, except in a slice holding several references, which carries no checksum (samtools does not notice either). A CRAM written with `no_ref` or `embed_ref` needs no reference, nor do `-g x.cram` and `gloci index x.cram`. MD and NM come out as stored: samtools recomputes them by default, so compare with `samtools view --input-fmt-option decode_md=0`. A CRAM cut short (no end-of-file container) is an error, not a warning. A read more than 1 Mb past its chromosome's end is refused (samtools decodes it), and a CRAM crafted with recomputed checksums can still end gloci with an internal error or exhaust its memory (docs/differences.md#cram-limits).
- **CRAM memory:** the decoder threads share one lease-based cache with one copy of each reference sequence they need, whatever `-t`, and read each from the FASTA once: sorted input holds at most two chromosomes at a time (about twice one while it loads; chr1 is 250 MB); with a `.crai` and `-t` above 1 a CRAM is read per chromosome, one chromosome per worker held until the worker moves on, so at most `-t` at once (at most 8 workers: 8 x 250 MB for chr1-sized chromosomes), and each chromosome read from the FASTA once; unsorted or name-sorted input keeps every chromosome its slices touch, as samtools does, and lets them go only when more than the longest chromosome's worth sits unused (small contigs stay). Up to 2 x `-t` containers are in flight. A CRAM written without a reference, in slices of several references, holds a zero-filled placeholder as long as each reference its slices touch, shared the same way.
- **`--split` is not `--split-deletions`:** on alignments, `--split` cuts a read at CIGAR `N` only (bedtools `-split`), and `--split-deletions` also cuts at `D` (bedtools `bamtobed -splitD`). `genomecov` of a BAM counts deleted bases by default, unlike `bedtools genomecov -ibam`: bedtools `-ibam -split` is `--split-deletions`, and `-split -ignoreD` is `--split`.
- **Unmapped reads are skipped by interval commands and kept by record commands:** `intersect`, `coverage`, `genomecov` and `convert` skip unmapped reads (flag `0x4`, placed or not; counted at `-v`), even with `intersect --mode none` (bedtools `-v` writes them). `view`, `sort`, `sort -m`, `cat` and `tag` keep every record. Filters default to nothing (`--min-mapq`, `--require-flags`, `--exclude-flags`); for `samtools depth` or mosdepth semantics pass `--exclude-flags 0x704`.
- **`--reference` is for CRAM only, and BED B files must follow the BAM's order:** a BAM or SAM never needs it (and `--reference` with no CRAM input warns). Alignments are sorted in the header's `@SQ` order, which beats `--chrom-order`: sort a B BED with `gloci sort b.bed -g x.bam`, or pass `--sort` (which also sorts BAM, CRAM and SAM inputs, bounded by `--max-mem`).
- **Seventeen commands read alignments:** `intersect`, `coverage`, `genomecov`, `convert`, `view`, `index`, `sort`, `cat` (BAM only), `idxstats`, `flagstat`, `check`, `reheader` (BAM or CRAM), `head`, `samples`, `depth`, `bedcov` and `tag`. Every other command exits 2 on a BAM, CRAM or SAM and names them; convert to BED first with `gloci convert x.bam`. Interval commands never build an index: `gloci index x.bam` or `--write-index` first, else regions and `-t` runs scan the file. FASTA needs `gloci index ref.fa` before `getfasta`, `nuc`, `faidx` or a CRAM `--reference` (never built implicitly; `maskfasta` streams and needs none).
- **`gloci merge` is not `samtools merge`:** `gloci merge` merges overlapping intervals and refuses alignment files, pointing at `gloci sort -m`, which merges already-sorted BAM, SAM or CRAM files as `samtools merge -c -p` does (`-n`/`-N` for name order; `@SQ` lists must be identical and a conflicting `@RG` is an error). Join BAMs without re-sorting with `gloci cat`.
- **`sort -n` is by read name and `windows -n` is a window count:** `gloci sort -n x.bam` sorts alignments by natural read name (`-N` by byte order), as `samtools sort -n`/`-N`; `gloci windows -n 10` cuts each interval into 10 windows. `sort -m` is merge, not memory: the memory budget is `--max-mem` (a total, where `samtools sort -m` is per thread). `sort` writes the input's format (SAM for SAM, BAM for BAM and CRAM), where samtools always writes BAM; pass `-O bam`.
- **BEDPE is never detected:** `pair-intersect` and `pair-pair` read A (and B for `pair-pair`) as BEDPE whatever it looks like, and `gloci shuffle` treats BEDPE as opt-in: pass `--format bedpe`, or the file is shuffled as BED. Make pairs from alignments with `gloci convert x.bam --bedpe` on a name-sorted BAM (`gloci sort -n`).
- **`convert --fastq` writes every record unless you filter:** `gloci convert x.bam --fastq -o r1.fq.gz --fastq2 r2.fq.gz` is bedtools `bamtofastq -fq -fq2`; secondary, supplementary, unmapped, QC-fail and duplicate reads are all written, so add `--exclude-flags 0x900` (secondary and supplementary) before pairing. `--fastq2` needs a name-sorted input (`gloci sort -n`; a coordinate-sorted file is exit 2) and a name with more than two records is an error, not a silent pick.
- **`vcf compare` matches by alleles unless `--match position`:** the default pairs records at one CHROM and POS that share an ALT allele after trimming; `--match position` pairs by POS and REF as vcftools `--diff` does, so pass it when reproducing vcftools. It is genotype concordance only: vcftools `--diff-site` and `--diff-indv` are `gloci intersect` / `gloci subtract --match alleles` and the `#CHROM` line.
- **`vcf popgen` is vcftools `--site-pi`, `--window-pi`, `--TajimaD`, `--weir-fst-pop`, the LD options and `--relatedness`/`--relatedness2`:** `gloci vcf popgen FILE --out-prefix P --site-pi --window-pi SIZE --tajima-d BIN --fst-pop POP1 --fst-pop POP2 --geno-r2 --ld-window-bp BP --relatedness2` writes vcftools' files in one run (`--TajimaD` is spelled `--tajima-d`, `--weir-fst-pop` is `--fst-pop`; `--geno-r2`, `--hap-r2`, `--interchrom-geno-r2`, `--interchrom-hap-r2`, the `--ld-window*` flags, `--min-r2`, `--relatedness` and `--relatedness2` keep vcftools' names). The windowed statistics (`--window-pi`, `--tajima-d`, `--fst-window-size`, `--geno-r2`, `--hap-r2`) need input sorted by chromosome and position, and a window step larger than the window is exit 2 where vcftools quietly resets it. LD holds the sites of its pair window in memory: without `--ld-window-bp` or `--ld-window` that is a whole chromosome, and past `--max-mem` (default 2G) the run exits 1. The population files select no samples, and `--hap-r2`'s phase rule removes no sites from the other statistics: to filter sites over the population members only, as vcftools does, also select them with `--samples-file`, and add `--phased-only` for vcftools' `--phased`. Relatedness reads a masked or half-called genotype as missing (vcftools counts masked ones in `--relatedness2`) and holds 8 or 12 bytes per pair of samples: 150 MB for 5,000 samples.
- **`sample` is not `samples`:** `gloci sample FILE -n N --seed S` draws a random subset of records (bedtools `sample`); `gloci samples` (samtools `samples`) lists the samples of read groups. `--seed` reproduces gloci's own output at any `-t`, never bedtools' for the same seed.
- **`--mode` has no `-m` short flag (and defaults to `any`):** `gloci intersect` defaults to `--mode any` (unique A records with a hit, like `bedtools intersect -u`), not coordinate clipping (`--mode clip`). Always spell `--mode` in full (`--mode any|none|pairs|clip|count`); `-m` is only `gloci sort -m` for merging pre-sorted files.
- **`depth` and `bedcov` exclude unmapped, secondary, QC-fail and duplicate reads by default:** unlike `coverage` and `genomecov`, which filter nothing, their `--exclude-flags` defaults to `UNMAP,SECONDARY,QCFAIL,DUP` as in samtools; `--exclude-flags 0` counts everything but unmapped reads, and samtools `-g DUP` is `--exclude-flags UNMAP,SECONDARY,QCFAIL`.
- **`check --quick --list-failed`, not `-v`:** `gloci check --quick --list-failed FILE...` prints only the failing paths (samtools `quickcheck -v`; gloci's `-v` is verbose logging). Any failing file exits 1, not samtools' bit mask; `-u` is `--unaligned` (no `@SQ` needed).
- **`view --count`, not `-c`:** `gloci view --count x.bam [REGION...]` is `samtools view -c` (`-c` is `COL:OP` in gloci); a read is counted once however many regions it overlaps, and `--regions-file` (samtools `-L`) combines with positional regions as a union.
- **`bedcov --split --split-deletions` is samtools `-j`:** by default `bedcov` counts `D` and `N` bases like `depth`; pass both flags to drop them. `--read-count` is `-c`, `--bases-at-depth N` is `-d`, and each BAM or CRAM needs an index.
- **`faidx` needs `gloci index ref.fa` first:** gloci never builds the `.fai` (or `.gzi`) implicitly, so `gloci faidx ref.fa chr1:1-100` on an unindexed FASTA exits 2 naming `gloci index ref.fa`; `-r FILE` is `xargs gloci faidx ref.fa < list` or `--regions-file BED`.
