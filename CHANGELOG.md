# Changelog

All notable changes to gloci are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/) (before 1.0, a breaking change bumps
the minor version).

## [Unreleased]

### Added

- `gloci convert peaks.bed --bam -g hg38 -o peaks.bam` turns BED, GFF or VCF features into BAM records, as bedtools `bedtobam` does, and `gloci convert pairs.bedpe --format bedpe --bam -g hg38` turns each BEDPE pair into two mated records, as bedtools `bedpetobam` does: `--mapq` sets the mapping quality and `--bed12` makes the blocks of a BED12 record its CIGAR. The header lists the genome's chromosomes in its order; a feature on a chromosome the genome lacks stops the run with a message instead of landing on another chromosome, and an absent BEDPE end (`. -1 -1`) becomes an unmapped mate.
- `gloci igv` writes the IGV batch script bedtools writes, a `goto` and a `snapshot` line for each feature of a BED, GFF or VCF file (`--path`, `--session`, `--sort`, `--collapse`, `--name`, `--slop`, `--image`), and `gloci links` writes the HTML page of UCSC Genome Browser links (`--base`, `--org`, `--db`). Both give the bytes `bedtools igv` and `bedtools links` give on the same file, read the features in file order without sorting, and are experimental.
- `gloci convert x.bam --fastq` turns a BAM, CRAM or SAM into FASTQ, as bedtools `bamtofastq` does: `--fastq2 r2.fq.gz` writes the second mates to their own file (the input sorted by name; `-o r1.fq.gz` names the first), `--tags` takes them from the R2 and Q2 tags, and every read is written unless you filter it (`--exclude-flags 0x900` leaves out secondary and supplementary alignments). Where bedtools writes each read twice, loses a pair or writes an empty read, gloci writes the right FASTQ or stops with a message (see the differences page).
- `gloci tag reads.bam -b genes.bed --labels genes` tags each read that overlaps a feature of the `-b` files, as `bedtools tag` does: the files' labels, or with `--names`, `--scores` or `--intervals` the name, score or whole interval of each feature, in a `YB` tag (`--tag` picks another), with `-s`/`-S` for strands and `-f` for the share of the read that must overlap. The tags are the ones bedtools 2.31.1 writes; the reads are written in input order and otherwise unchanged, from BAM, CRAM or SAM. Experimental.
- `gloci vcf popgen` computes vcftools 0.1.16's population genetics statistics, in its file formats, any of them in one run after the usual `vcf` selection flags: nucleotide diversity per site (`--site-pi`) and in windows (`--window-pi`, `--window-pi-step`), Tajima's D in bins (`--tajima-d`), Weir and Cockerham's Fst between populations, linkage disequilibrium and the relatedness of every pair of samples. The windowed statistics need sorted input, a window step larger than the window is an error rather than quietly reset, and no count wraps at vcftools' 32-bit limits (from about 23,000 samples), so large cohorts get the right numbers. `--fst-pop FILE` (once per population, at least twice) computes Fst as vcftools' `--weir-fst-pop` does: per site, in windows with `--fst-window-size` and `--fst-window-step`, and as a summary file with the mean and weighted estimates that vcftools only prints in its log. The population files leave the samples, site filters and other statistics of the run as they are, and a single population, a population with no selected sample or a sample in two populations is an error, where vcftools quietly writes nothing, `nan` rows or a double-counted estimate. `--geno-r2` (the squared correlation of genotypes) and `--hap-r2` (r², D and D′ of phased haplotypes) give pairs of sites on one chromosome, chosen with `--ld-window`, `--ld-window-bp`, `--ld-window-min` and `--ld-window-bp-min`, and `--interchrom-geno-r2` and `--interchrom-hap-r2` every pair on different chromosomes, with `--min-r2` to drop weak pairs. The sites LD holds stay within `--max-mem` (2G unless you say otherwise): past it the run stops and says how to narrow the window, where vcftools quietly fills a temporary file. `--hap-r2` uses only fully phased sites without removing them from the other statistics of the run, and a window that admits no pair is an error rather than an empty table. A sample without GT counts as unphased, as vcftools reads it. `--relatedness` (Yang's unadjusted Ajk) and `--relatedness2` (Manichaikul's kinship φ, with the counts it comes from) give every pair of selected samples, the same at any `--threads`. They count a genotype only when both its alleles are called and it is not masked, where vcftools counts masked genotypes in `--relatedness2`, which makes a parent and child with low-depth calls look unrelated, and reads `./1` as `0/0` in `--relatedness`.
- The VCF commands `vcf filter`, `vcf extract`, `vcf stats` and `vcf concat`.
- BAM, CRAM, SAM and FASTA input; the samtools-style commands `sort`, `merge`, `cat`, `index` and `faidx`; and `getfasta`, `nuc` and `maskfasta`.
- `stats jaccard`, `fisher` and `reldist`; `random`, `sample` and `shuffle`; the BEDPE pair commands and `convert --bedpe`; parallel VCF selection; `vcf compare` (genotype concordance); and `vcf split`, `vcf norm`, `vcf annotate` and `vcf merge`.
- The samtools-style commands `flags`, `idxstats`, `flagstat`, `head`, `samples`, `depth` (with `--skip-mate-overlap`), `bedcov`, `dict` and `reheader`; `check` of alignment files and `check --quick` (quickcheck); and `view --count` and `view --regions-file` on alignments.
- `gloci::embed`, the in-process API the Python library is built on: the CLI's own parsing and dispatch with in-memory inputs and outputs, per-run cancellation, command specs and keyword arguments.
- The Python library `gloci` (crate `gloci-py`, built with maturin): lazy, immutable pipelines over files with one step method per stream command, run in-process with the CLI's output (`save()`, `to_bytes()`, `count()`, `cli()`); typed exceptions (`UsageError`, `DataError`, `UnsortedError`, `GlociError`); the GIL released while steps run, Ctrl-C cancelling the run, and warnings sent to the `logging` logger `gloci`.
- The documentation site (mdBook): install, quickstart, semantics, migration, differences, the generated per-command reference, the Python guide and API, and the maintainers' release checklist; `cargo xtask book` generates the reference and checks every link.
- Python-object sources for the Python library: file objects, iterables of lines or tuples, Arrow tables and streams (pyarrow, polars, pandas; read through the Arrow C stream interface) and nested pipelines, read as the run goes; the module sources `gloci.windows()` and `gloci.random()` and the functions `vcf_stats()`, `vcf_extract_matrix()`, `vcf_compare()`, `vcf_popgen()` and `index()`. `sort(check=True)` is refused on the step: the check stays on the command line.
- The Python library has the steps `tag()`, `igv()` and `links()`, and `convert()` takes the keywords of `--fastq` (`fastq=`, `fastq2=`, `tags=`) and of `--bam` (`bam=`, `genome=` or `g=`, `mapq=`).
- Records and tables from the Python library: iteration yields `gloci.Record`s (coordinates read back with gloci's readers, fields and line), handed over in 4 MiB batches with the steps stopped by `break`; `count()` counts what iteration yields, in Rust; `to_arrow()`, `to_polars()`, `to_pandas()` and `to_arrow_stream()` (a `gloci.ArrowStream`, through the Arrow PyCapsule interface; polars needs no pyarrow) build a table with `chrom start end` first and inferred column types. A step whose output is a table (`stats jaccard`, `vcf extract`, `idxstats`, ...) is marked in `gloci::embed`, so its header row names the columns rather than being a record.
- `idxstats` and `head` take `-o FILE` (atomic; a `.gz` name compresses).
- The release archives carry the man pages, the shell completions and `CHANGELOG.md` next to the binary, `SKILL.md` and the licence.
- Python wheels (abi3, for CPython 3.10 and later; manylinux2014 on x86_64 and aarch64, macOS arm64), an sdist, and bioconda recipes for `gloci` and `py-gloci`; each release carries them with `SHA256SUMS`. Publishing to PyPI, crates.io, `ghcr.io` and GitHub Pages stays off until the owner enables it.
- The Python package is typed: `py.typed` and a generated stub (checked by `mypy --strict`), runtime signatures and docstrings from the CLI definition, and a Python guide in the book.
- The Python extras need pyarrow 15, polars 1.5 and pandas 2.2 or later (the lowest versions whose Arrow stream interface gloci uses); CI runs the tests on exactly those.
- Stability tiers: `genomes`, `index`, `sort`, `view`, `intersect`, `merge`, `subtract`, `closest` and `coverage` are the stable core; every other command is experimental and its help starts with a line saying so. `contrib/gloci-shadow.sh` runs a pipeline step with the tool it uses today and with gloci, and logs whether the outputs are identical.
- The README has a performance table from the real-data benchmarks (indicative: a 4-core aarch64 machine), including the cases where samtools or bcftools is faster. The benchmark commands were audited by comparing what each tool writes (`paper/README.md`): bedmap now reads a five-column copy of the signal (on the bedGraph it printed `NAN` and read nothing), `exons.bed` is in the sort-bed order bedops needs, every command asks for the threads its case states, `gloci-merged`, `gloci-each-side` and `gloci-merge-adjacent` do the work of `bedops -d`, `closest-features` and `multiinter`, and the nightly `bedtools intersect` commands have `-u`.
- The benchmark runner checks that the commands of a case give the same result before it times them: a case lists the commands that must agree and how (`[[case.same]]`: byte for byte, as unordered or distinct lines, numerically, as VCF records or sites, as decoded BAM or BCF records), or says why a command is compared with no other (`[case.not_compared]`), and a test fails for a case that does neither. `cargo xtask bench --verify-only` and `cargo xtask paper run --bench-only --verify-only` compare without timing; a case whose commands disagree is not timed and fails the run. In the nightly cases every command now asks for its threads itself (gloci `sort` and the `vcf` commands had none and used every core), and `subtract` and `closest` are compared with bedops through `gloci-merged` and `gloci-each-side`, which do bedops' work. The first run of the check over the nightly cases found two more that were not the same work, and both are corrected: `bedtools genomecov -ibam` counted the introns of spliced reads where `gloci --split-deletions` cuts at them (bedtools now has `-split`), and `bedtools pairtopair` enforced strand where `gloci pair-pair` ignores it (bedtools now has `-is`).
- `docs/differences.md` records that `bedtools genomecov` adds its `genome` rows up in 32 bits, so they wrap for a genome of more than 2^32 bases; gloci's do not (`#genomecov-genome-total`, pinned by a differential case).
- Fuzzing: `cram_reader` and `fasta_index` targets; the nightly job runs every target (it left out `sam_reader` and `bedpe_reader`) for 180 s each.

### Changed

- Without `-g` and without a VCF/BCF header that lists contigs, gloci now orders chromosomes lexicographically (`chr1, chr10, chr2 ... chrX`), the order of `bedtools sort`, `sort-bed` and `LC_ALL=C sort -k1,1`, where it used karyotype order (`chr1, chr2 ... chr22, chrX, chrY, chrM`). Files from those tools work as they are and `gloci sort` writes the same bytes as they do. `--chrom-order karyotype` gives the old order. A file in karyotype order (for example the BED that `gloci convert` makes from a VCF or BAM) is now the one reported as not sorted, with a hint to pass `-g GENOME` or `--chrom-order karyotype`, or to re-sort it with `gloci sort`. `-g`, a built-in genome (still in karyotype order) and the contig order of a VCF/BCF or alignment header still win.
- `--thin` in `vcf filter`, `extract`, `stats` and `popgen` needs each chromosome's records together, by position, in any chromosome order (what tabix needs, and what the windowed statistics need), where it needed the chromosome order: a VCF in reference order without `##contig` lines is thinned as it is. The hint of an order error in `vcf concat`, `merge` and `annotate` suggests `--chrom-order karyotype`, not `-g`, which they do not take.
- `vcf filter --phased-only` treats a selected sample without GT as unphased, as vcftools `--phased` does, so it drops the site; it used to keep it.
- The design specification is `docs/design.md` and the numbered design decisions are `docs/decisions.md`; the source cites both by section (`spec §4.3`) and by number (`D37`).
- `gloci --help` lists the commands in groups (the stable core first, then the experimental groups), with a one-line summary for each. The `--help` of a command now opens with a short summary, then the usage and the options, then the examples and the detail under headings.
- CI builds with a pinned Rust (1.100.0, set in `rust-toolchain.toml`) instead of the newest stable, and a new `msrv` job checks that the workspace builds with the minimum supported Rust (1.91), so a new Rust release no longer changes a build by itself.
- `gloci stats --help` names all three of its commands (`jaccard`, `fisher` and `reldist`) and shows an example of each.
- `flagstat` on a CRAM decodes only the data series it counts, and reads the same counts as before: a 258 MB CRAM of 7.5 million reads takes about 0.27 s where it took 13.4 s, against 0.45 s for `samtools flagstat` (output byte-identical, in text, JSON and TSV, at every `--threads`).
- `idxstats` and `view --count` (without regions) on a CRAM decode only the data series they count, as `flagstat` does, and give the same numbers as before. Checks on fields they no longer read (a read far past its reference's end, a `--reference` with other bases) no longer apply to them, as for `samtools idxstats` and `view -c`; `gloci check` still decodes every record.
- `SKILL.md` is an index of 28 KB where it was 173 KB: the semantics, one entry per command and the pitfalls. The rules of a command stay in its `--help`, and the release archives now carry `docs/migration.md` and `docs/differences.md`, which it points to.
- Help text no longer cites sections of the internal design spec. `docs/migration.md` no longer lists `jaccard`, `fisher`, `reldist`, `shuffle`, `random`, `sample`, `pairtobed` and `pairtopair` as not yet available: they are available.
- `vcf filter` on a BCF is faster where it filters on what the genotypes count to (`--min-maf`, `--max-missing` and the other statistics filters): a record's genotypes are counted from the bytes of its GT field, not one decoded sample at a time. On the 1000 Genomes chr20 panel (3,202 samples, a 535 MB BCF), `vcf filter --min-maf 0.01 --max-missing 0.1` writing `.vcf.gz` takes 69 seconds of user CPU time on one thread where it took 174 (timed back to back on a loaded 4-core machine; the 30 seconds of system time, mostly reading the file, did not change), and its output decompresses to the same bytes as before, at every `--threads`. Most of what is left is compressing the output and writing the VCF text. `vcf extract` and `vcf stats` count the same way when they read a BCF and need a site's counts but not its samples.
- With `--threads` above 1, the threads of the `vcf` commands that filter records sleep while they wait for each other. They waited by yielding the CPU, which on a busy Linux machine costs a scheduler slice at every wait.
- With `--threads` above 1, the threads that decompress BGZF input (`.gz`, BCF, BAM) and compress BGZF output sleep while they wait for each other too, in every command; they also waited by yielding the CPU, so a run on a machine whose cores are busy, or with more threads than the machine has cores, lost time at every block. On a 4-core machine busy with other work, `view` of a 216 MB `.bed.gz` to a `.bed.gz` at `--threads 8` has the kernel take the CPU away from its threads 12,000 times where it did 300,000 to 430,000 times; `vcf filter` of the 535 MB BCF above, writing `.vcf.gz`, is interrupted 75,000 times where it was 2.3 to 2.7 million times. The compressed output is the same bytes as before at every `--threads`, and a truncated or corrupt input fails with the same message.

### Fixed

- BCF records are written as VCF text the way htslib writes them, byte for byte as bcftools 1.21 prints them: strings as stored (a `,`, `;`, `=` or `%` in a value is no longer percent-encoded, so `SOURCE=novelins,gatksv` stays that), numbers in htslib's notation (`8.08575e-05`, not `0.0000808575`), and a genotype with an allele index of 63 or more is written where it was an error. This is every command that reads BCF and writes text (`view -O vcf`, `vcf filter`, `vcf split`, `vcf norm`, `getfasta`, the Python records). On the 1000 Genomes chr20 panel the 370,398 records `vcf filter` keeps are identical to bcftools', and rendering them takes a tenth of the time.
- `coverage` writes its fractions and mean depth as bedtools does: seven decimals of a 32-bit quotient (`0.4347826`, where it wrote `0.43478260869565216`), and six decimals of a 64-bit one in the report of several `-b` files (`bedtools annotate`). The counts were already equal; now the bytes are.
- Messages that sent users the wrong way, and a misread `-g` BAM: a region such as `{chr1}x` is reported as unexpected text after the `}`, where it was called an unterminated `{`; an `INFO/SVLEN` whose end passes the largest coordinate is "too large", where it was "not an integer" (and lost its minus sign); errors in a `-g` genome file with blank lines before its first line name the right line, and header errors in a `-g` VCF no longer claim line 1; `--write-index` on a command whose output is not sorted (`slop -s`) says the output was not written and to pipe it through `gloci sort`, where it said to sort the file it had not written; `view` with regions on a pipe or a `/dev/fd` path (`<(...)`) scans it as it scans stdin, where it suggested writing `/dev/fd/63.gz`. A `-g` BAM whose reference name is stored without its closing NUL keeps the name's last letter, as htslib does, where gloci dropped it.
- A usage message that names the long option now says `--output-format` where it said `-O`.
- A command given `-` (standard input) for two of its inputs, such as `gloci intersect -a - -b - < a.bed`, stops with a usage error (exit 2) that names both (`standard input is given for both -a and -b; give one of them as a file`) before it reads or writes anything. It read standard input for the first input and found the second empty, so it wrote a wrong answer (often nothing) and exited 0; `subtract`, `closest`, `coverage`, `merge - -`, `sort - -`, `view - --regions-file -` and every other command with two inputs did the same. `vcf compare` and `tag`, which refused it already, now say so in the same words. `-` given once works as before, and each run of the in-process API and the Python library is checked on its own.

## [0.1.0] - 2026-11-08

- Interval engine: half-open u64 coordinates, sorted-stream sweeps and an index for random access, with output byte-identical at every `--threads`.
- Interval commands with bedtools parity: intersect, merge, subtract, closest, coverage, genomecov, map, groupby, cluster, spacing, window, slop, flank and more, checked against pinned bedtools output through committed golden files.
- BED, GFF, VCF and BCF reading and writing, with bgzip and tabix (TBI and CSI) indexes, and built-in genome files.
- A single static binary (musl on Linux, plus macOS arm64) with man pages, shell completions and an agent usage guide (`SKILL.md`).
- A differential test harness (`cargo xtask diff`), a benchmark suite (`cargo xtask bench`) and synthetic data generators (`cargo xtask gen`).
