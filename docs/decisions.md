# gloci design decisions

Every numbered design decision the project made while gloci was built, in numeric order, D1 to D164. A decision
records a point the design specification ([`design.md`](design.md)) left open or got wrong, what was chosen, and
usually why. The source cites them by number in comments and tests (`D37`, `(D37)`, `D37/D38`), and the text
sometimes cites a section of the specification as `spec §4.3`.

Each decision has an anchor, so a link such as `decisions.md#d157` goes straight to it. A decision that a later one
replaces says so after its number. A reference to a task (`P3a Task 18`) names the phase and the task of that
phase's implementation plan.

The decisions are grouped by the phase that made them:

- P0 foundations
- P1 core replacement
- P2a breadth
- P2b Python library, packaging and paper evidence
- P3a sequence and alignment I/O
- P3b analysis
- P3c samtools essentials

## P0 Foundations

D1–D33, from the plan "Decisions this plan adds" table.

<a id="d1"></a>**D1** `RecordMeta` carries both `key` (the position the file is sorted by: BED start, GFF start−1, VCF POS−1) and `span` (the footprint). Sortedness is checked on `(chrom, key)`.

<a id="d2"></a>**D2** `sort` orders VCF/BCF by the `ref` span (`POS`, then ref end), whatever `--vcf-span` says, so sorted VCF is always tabix-compatible.

<a id="d3"></a>**D3** The atomic temp file always sits next to `PATH` so the rename stays on one filesystem. `--tmp-dir` controls only `sort` spill files.

<a id="d4"></a>**D4** `-f/-F` fractions are parsed as exact decimals and compared with integer arithmetic, so `0.3` of 10 bases is exactly 3.

<a id="d5"></a>**D5** (replaced by D34) `--min-bases` counts as met when either side is a point, the same as the point rule for fractions.

<a id="d6"></a>**D6** Under `--signed a` or `--signed b`, an unknown strand is treated as `+`.

<a id="d7"></a>**D7** A chromosome missing from `--genome` is an error. When a VCF header declares contigs, a record on an undeclared contig is an error. A header with no contigs falls through to lexicographic order.

<a id="d8"></a>**D8** Region strings accept `chr`, `chr:s`, `chr:s-`, `chr:s-e` and `{name}:s-e`, with commas allowed in numbers. If the whole string is a known chromosome name, it means that chromosome. Otherwise it is split at the last `:`. If both readings are valid names, it is an error (samtools behaviour).

<a id="d9"></a>**D9** `view` region queries select records whose footprint (per `--vcf-span`) overlaps the region under §4.3, so an insertion on a region edge is excluded by default. `--vcf-span ref --inclusive-points` reproduces tabix. This goes in `docs/differences.md`.

<a id="d10"></a>**D10** `view` sorts and merges the requested regions, so each record is printed once, in file order.

<a id="d11"></a>**D11** (Revised 2026-11-07 after the P0 Task 17 review.) For uncompressed BED without an index, `view` scans the whole file under a first-appearance `OrderGuard` by default, so an unsorted file is an error. With `--assume-sorted`, it binary-searches to the first line of the region's chromosome and scans that chromosome, falling back to a full scan with a warning if the search can't find the chromosome. Help text and `docs/differences.md` state that `--assume-sorted` trusts the user's sort order.

<a id="d12"></a>**D12** `sort --check` checks `(chrom, start)` order, which is what streaming commands need.

<a id="d13"></a>**D13** `--unique` and `--duplicates` imply `--full-key` and behave like `uniq` and `uniq -d` on whole lines.

<a id="d14"></a>**D14** BED header lines (`#`, `track`, `browser`) before the first record are kept only with `--header`, and such lines after the first record are dropped. Blank lines are skipped. In GFF, leading `#`/`##` lines form the header, `###` lines are dropped, and `##FASTA` is an error in P0.

<a id="d15"></a>**D15** CRLF input is accepted, and output always uses LF.

<a id="d16"></a>**D16** bedGraph is detected only from a `track type=bedGraph` line or `--format bedgraph`; anything else BED-shaped is BED.

<a id="d17"></a>**D17** Output format comes from the `-o` extension (case-insensitive), or from `-O` for stdout. If both are given they must agree. Default: the input's format, uncompressed, on stdout. BCF or BGZF output to a terminal is a usage error.

<a id="d18"></a>**D18** `sort` doesn't convert formats (the `-o` family must match the input). VCF↔BCF conversion is `view`'s job. Other conversions are `convert` (P1).

<a id="d19"></a>**D19** When gloci replaces `PATH`, it deletes any existing `PATH.tbi`/`PATH.csi` unless it writes a fresh index. Stale indexes are never left behind.

<a id="d20"></a>**D20** Indexes are built in a second pass over the finished temp file. TBI is used unless a record's end exceeds 2^29, in which case CSI is used (min_shift 14, depth chosen to cover the largest end). BCF always gets CSI. Index spans use the ref span, extended by INFO/END when present (a superset of htslib's span, so htslib queries stay correct). A zero-length BED record is indexed as `[s, s+1)`.

<a id="d21"></a>**D21** `--compression-level` accepts 0–12 (libdeflate's range).

<a id="d22"></a>**D22** BCF fast path: hand-written record framing and a minimal typed-value decoder (CHROM, POS, rlen, alleles, INFO/END, INFO/SVLEN), verified against noodles. BCF↔VCF conversion uses noodles. VCF headers are parsed by hand for `##contig` and `#CHROM` only, so real-world headers that noodles rejects still work.

<a id="d23"></a>**D23** `--max-mem` takes binary units (`K`, `M`, `G`, `T` = powers of 1024), with a minimum of 16M.

<a id="d24"></a>**D24** Spill files are LZ4 frames (`lz4_flex`) in a temp directory under `--tmp-dir`, then `GLOCI_TMPDIR`, then the system temp dir. Merge fan-in is 128. Chunk boundaries depend only on `--max-mem` and the input, never on threads.

<a id="d25"></a>**D25** In `check`, duplicates are warnings (exit 0). Parse, order and bounds problems are errors (exit 1).

<a id="d26"></a>**D26** An index older than its data file triggers a warning (htslib behaviour).

<a id="d27"></a>**D27** `--genome` accepts a BAM header now, since it is a small binary parse.

<a id="d28"></a>**D28** VCF `POS 0` is invalid. REF/ALT comparison is ASCII case-insensitive. `END` is used only for records with a symbolic ALT.

<a id="d29"></a>**D29** Multiple VCF inputs to `sort` must have identical sample columns; the header comes from the first file.

<a id="d30"></a>**D30** A seekable BGZF file without the 28-byte EOF marker is an error ("probably truncated"). stdin can't be checked.

<a id="d31"></a>**D31** Being killed by SIGINT, SIGTERM or SIGHUP removes registered temp files and spill dirs, then exits 130. A panic hook does the same before abort.

<a id="d32"></a>**D32** (User decision, 2026-11-07, spec §4.5 rule 3.) The fallback chromosome order is **karyotype**: `chr` ignored; numeric names (optionally followed by letters) by number, then X, Y, M/MT, then the rest in natural order, ties broken by raw bytes. `--chrom-order lex` restores lexicographic order. When a karyotype-mode order error looks like a lexicographically sorted file, the hint says so and gives both fixes. Users get `docs/migration.md`. Added as P0 Task 14b.

<a id="d33"></a>**D33** (User request, 2026-11-07, spec §5.3.) `-g` accepts a built-in genome name (`hg38`, `GRCh38`, `mm39` …) or a file. Value with `/` or naming an existing file → file; otherwise built-in lookup (case-insensitive); unknown → usage error with "did you mean". UCSC and Ensembl naming are separate entries from their own sources. Built-ins are in karyotype order (Roman-numeral genomes keep reference order). Data is committed and compiled in. `gloci genomes [show NAME]`. Added as P0 Task 23.

## P1 Core replacement

D34–D60, from the plan "Decisions this plan adds" table.

<a id="d34"></a>**D34** Every threshold (`-f -F -r -e --min-bases`) counts as met when either side is a point (spec §4.3, amended). Supersedes D5. `-r` with only one of `-f`/`-F` applies that one fraction to both sides.

<a id="d35"></a>**D35** `intersect --mode` has no short flag (spec §7.1, amended).

<a id="d36"></a>**D36** The engine yields **candidate hits**: every B whose window-padded span overlaps A's span under the exact §4.3 rule (with `--inclusive-points` when given). Thresholds and strand rules are applied by the reporting layer through `OverlapCriteria`, measured against the **unpadded** B span.

<a id="d37"></a>**D37** `-w`/`--left`/`--right` cannot be combined with `-f`/`-F`/`-r`/`-e`/`--min-bases` (usage error, exit 2). bedtools `window` has no fractions either, and a fraction of a padded interval has no clear meaning.

<a id="d38"></a>**D38** Hits for one A are ordered by B file (command-line order), then B input order. A records are reported in A's input order, in every mode, sorted or unsorted.

<a id="d39"></a>**D39** Two flags, one meaning each (revised 2026-11-08 with the user). **`--unsorted`** = "my input is in some order; work with it as it is": on `intersect`, `subtract`, `closest`, `map` and `coverage` only, all `-b` files are loaded into memory, A is streamed in any order, and results follow A's input order. **`--sort`** = "sort my inputs first": on `merge`, `complement` and the same five relation commands, all inputs go through the P0 external sorter (bounded by `--max-mem`, default 2G, spilling to `--tmp-dir`) and the normal streaming pass runs on the sorted streams, so results are in sorted order and equal `gloci sort …` piped into the command. `--sort` and `--unsorted` together are a usage error. An order error's hint names the flags the command offers. `windows -i` and transforms need neither.

<a id="d40"></a>**D40** Unsorted index: coitrees for a chromosome whose padded B coordinates all fit in `i32`. Otherwise an own `u64` implicit augmented interval tree (cgranges-style), `ITree64`. Queries are widened by one base on each side, and every candidate is re-tested exactly (spec §8.2). P1 Task 27's benchmark may swap the default with evidence.

<a id="d41"></a>**D41** Per-chromosome parallelism is automatic when A and every B are regular BGZF files with a `.tbi`/`.csi` and `--unsorted` is not given. It applies to `intersect`, `subtract`, `closest`, `map` and `coverage`. Each chromosome's output goes to a chunk that keeps its first 64 MiB in memory and spills the rest to an LZ4 file in `--tmp-dir`. Chunks are written in chromosome-table order, and at most `threads` are in flight. The output equals the streaming path byte for byte.

<a id="d42"></a>**D42** Appended-column output is TSV. `.tsv`/`.tsv.gz` (or `-O tsv`) always work. When A is BED-family, `.bed`/`.bed.gz`/`.bedgraph` also work, since the result is BED-like. Any other extension is a usage error. Stdout defaults to TSV. VCF A gets the line `#CHROM\tPOS\tID\tREF\tALT\tQUAL\tFILTER\tINFO[\tFORMAT\t<samples>]\t<appended names>`. BED/GFF A get their header lines only with `--header`.

<a id="d43"></a>**D43** `--write-index` on TSV output is allowed when A is BED-family; the index uses columns seq 1, begin 2, end 3, zero-based. For VCF or GFF A it is a usage error whose hint gives the matching `gloci index -s … -b … -e …` command.

<a id="d44"></a>**D44** Coordinate rewriting (`--mode clip`, `subtract` pieces, `slop`, `flank`): BED columns 2–3; GFF/GTF columns 4–5 written as 1-based closed. BED12 thick and block columns are left unchanged (bedtools behaviour). `--mode clip` with VCF/BCF A is a usage error ("a variant cannot be clipped; use --mode any").

<a id="d45"></a>**D45** Placeholders for a missing B (`--mode pairs --keep-unmatched`, `closest` with no candidate), byte-for-byte as bedtools 2.31.1 writes them (revised after P1 Task 9's differential cases): BED-family `. -1 -1` then `.` per further column, with `-1` in the score column (BED5+); GFF `. . . -1 -1 . . . .`; VCF `. -1 . . . . . .`. A missing distance is `-1`.

<a id="d46"></a>**D46** P1 aggregation ops: `count count_distinct sum mean median min max stdev var stdev_pop var_pop collapse distinct distinct_sorted first last bases indicator` (`stdev_pop`/`var_pop` added during P1 Task 14 so bedtools' population `stdev` can be reproduced). Any other spec §6.3 op (P2) is a usage error ("… is not available yet"). Value rules: `.` or empty values are missing. A value that isn't a number in a numeric op is a data error naming the file, line, column and op. `sum`/`min`/`max` print as integers when every input value was an integer literal. Other floats print in Rust's shortest round-trip form. With no values, `count`/`count_distinct` print 0 and the others print `--empty` (default `.`). `stdev`/`var` are sample statistics, and with one value they print `--empty`. `distinct` keeps first-seen order; `distinct_sorted` sorts bytewise. COL `0` is allowed only with `count`, `bases` and `indicator`.

<a id="d47"></a>**D47** `merge -s` keeps clusters separate per strand but adds no strand column (bedtools). Output is sorted by chromosome, start, end.

<a id="d48"></a>**D48** `complement` ignores points, since they cover no bases. Without `-g` it reports only gaps between features on the same chromosome.

<a id="d49"></a>**D49** `slop`/`flank` accept BED and GFF/GTF; VCF/BCF input is a usage error. `-s` treats unknown strand as `+`. A transform output that breaks sort order prints one warning naming the first out-of-order line, with the hint `pipe the output through gloci sort`.

<a id="d50"></a>**D50** `vcf filter` rules: <ul><li>A genotype is **missing** when any of its alleles is missing or GT is absent.</li><li>Masking sets every allele missing, keeping the ploidy and separators.</li><li>Missing DP or GQ never triggers masking.</li><li>FT passes when it is `PASS`, `.` or absent.</li><li>A missing QUAL fails `--min-qual`.</li><li>`--pass-only` keeps FILTER `PASS` and `.`.</li><li>A record's **type set** is the union of its ALT kinds. `--types` keeps a record whose set meets the list, and `--exclude-types` drops one whose set meets it. `indel` is `ins` or `del`.</li><li>`--min-alleles`/`--max-alleles` count listed alleles (REF plus ALTs; ALT `.` gives 1).</li><li>`--thin` runs after every other site filter.</li><li>Dropped INFO keys also lose their `##INFO` header lines.</li><li>`--recalc-ac` writes AF like C `%g` (6 significant digits).</li></ul>

<a id="d51"></a>**D51** Relation chromosome table: `chrom_table_for(-g, [A, B…], --chrom-order)`, so the first VCF/BCF header among A then the Bs wins. Every input is order-checked against that one table.

<a id="d52"></a>**D52** `--region`/`--regions-file` exist on `view` (P0) and `vcf filter`. On the relation commands they are deferred to P2.

<a id="d53"></a>**D53** The mdBook and the bioRxiv external benchmark datasets are deferred to P2.

<a id="d54"></a>**D54** Strand comes from BED column 6 when the line has at least 6 columns and the value is `+`, `-` or `.`, and from GFF/GTF column 7. Anything else, and all VCF/BCF records, is unknown. `-s`/`-S` warn once per input that has unknown-strand records.

<a id="d55"></a>**D55** `closest` also takes `-s`/`-S` (bedtools users rely on "nearest gene on the same strand"). The engine keeps neighbour candidates per (file, strand) when a strand rule is active.

<a id="d56"></a>**D56** `coverage` of a point A: count of B overlapping it (spec §4.3), bases 0, length 0, fraction `.`; `--mean` prints `.`; `--hist`/`--per-base` print no lines for it.

<a id="d57"></a>**D57** With several `-b` files: `--mode count` reports the total. `--mode pairs` and `closest` insert a label column (from `--names`, else the basename) before B's columns. `coverage` reports one covered fraction per file (bedtools `annotate`) and allows only the default report. `map` needs all `-b` files in one format family.

<a id="d58"></a>**D58** Chromosome naming. After a relation (or a multi-input `merge`/`complement`) in which two inputs with records shared no chromosome names, gloci warns. When adding or removing `chr` would make names match, the warning says so. A record on a chromosome missing from a built-in `-g` genome adds a hint naming the matching genome in the other naming style (`hg38`↔`GRCh38` and so on) when that genome has it.

<a id="d59"></a>**D59** The release workflow runs only on a pushed `v*` tag. It builds static musl x86_64/aarch64 and macOS aarch64 archives with SHA-256 sums, attaches them to the GitHub release and pushes a `ghcr.io` image. It publishes nothing to crates.io or bioconda while the licence is open (spec §13).

<a id="d60"></a>**D60** `subtract --split` removes B's blocks (exons) from A's span. `subtract --sum-overlaps` removes A when the summed overlap lengths of the B records passing the strand rule reach `-f` of A (bedtools `-N`). It takes only `-f`; `-F`/`-r`/`-e` with it are usage errors.

## P2a Breadth

D61–D78, from the plan "Decisions this plan adds" table.

<a id="d61"></a>**D61** The unsorted index switches from coitrees to **rust-lapper**, by the D40 rule. P1's real-crate benchmark measured rust-lapper 2.02× and 1.80× faster on both synthetic sets. rust-lapper is generic over `u64`, so `ITree64` and the i32 fallback are removed. Queries are still widened by one base on each side and every candidate is re-tested exactly. `unsorted_equals_sorted` must keep passing unchanged.

<a id="d62"></a>**D62** `--chrom-map FILE`, a global option on every command that reads intervals or variants. <ul><li>The file has two tab-separated columns, `old new`, with `#` comment lines allowed.</li><li>A duplicate `old` value is a usage error. An unmapped name passes through unchanged.</li><li>Renaming happens in the readers before interning, so order checks, `-g` lookups and indexes all see the new name. That includes VCF/BCF header contig lines.</li><li>Output records carry the new name: BED/GFF/VCF text records get their chromosome column rewritten, and BCF output gets a renamed header dictionary.</li><li>Index queries translate a requested region name back to the file's own name.</li><li>`-g` names are never renamed.</li></ul>

<a id="d63"></a>**D63** WIG (`fixedStep`/`variableStep`, with optional `span`) is detected from its first step line and read as bedGraph-like records (chrom, start, end, value). `track` and `browser` lines are header lines. WIG works wherever an interval input is accepted, with value column 4, and `gloci convert` turns WIG into bedGraph (one row per WIG data line, no merging of equal values).

<a id="d64"></a>**D64** The remaining spec §6.3 ops: <ul><li>`cv` = sample stdev ÷ mean (`--empty` when the mean is 0).</li><li>`mad` = median of absolute deviations from the median, unscaled.</li><li>`quantile:Q`, Q ∈ [0,1], uses linear interpolation (type 7).</li><li>`tmean:LO-HI`, LO < HI ∈ [0,1], is the mean of the values whose rank fraction lies in [LO, HI] (as `quantile`).</li><li>`wmean` is the mean weighted by overlapping bases; it is valid only in two-input commands.</li><li>`mode` and `antimode` are the most and least frequent value (compared as text, missing values skipped); ties go to the byte-wise smallest value, as in bedtools [revised in P2a Task 6 review].</li><li>`bases_uniq` is the union of overlapping bases.</li><li>`frac_a` = `bases_uniq` ÷ A's length (`.` for a point A). `frac_b` = summed overlap ÷ summed B length.</li><li>`min_record`, `max_record` and `records` write whole B records into one cell. Inside a record, tabs become `\|`; records are separated by `--delim`. They are valid only in two-input commands.</li></ul>

<a id="d65"></a>**D65** `cluster` appends a cluster id. Ids are global and increase through the file, as bedtools does. `-d/--max-gap` and `-s` mean the same as in `merge`.

<a id="d66"></a>**D66** `spacing` appends the distance to the previous record on the same chromosome, following the bedtools convention; differential cases decide the exact edges. That is `.` for the first record and 0 for bookended records; for overlapping records the bedtools value is pinned, or documented as a difference.

<a id="d67"></a>**D67** `groupby -g COLS -c COL:OP…` groups consecutive lines whose key columns are equal, without requiring sort order (bedtools semantics). <ul><li>Output is the group's key columns followed by the aggregations.</li><li>It works on any tab-separated text, including BED. VCF input is a usage error that suggests `vcf extract`.</li><li>`--header` takes key names from the header line.</li></ul>

<a id="d68"></a>**D68** `partition` follows spec §7.2. <ul><li>Membership is written as two columns: a count, then the labels joined with commas. Labels come from `--names`, defaulting to basenames.</li><li>With `--bedgraph`, each input contributes one value column instead of membership. Gaps are filled from `--empty`, and `-g` together with `--empty` covers the whole genome.</li><li>Points contribute no segments, since they cover no bases.</li><li>Inputs are k-way merged and order-checked; `--sort` is available.</li></ul>

<a id="d69"></a>**D69** `genomecov` (BED in P2a; BAM is P3) follows bedtools `genomecov`. <ul><li>`-g` is required.</li><li>Modes: `--hist` (the default) gives per-chromosome rows plus `genome` rows. `--bedgraph` and `--bga` (the latter including zero-depth runs) give runs. `--per-base` is 1-based. `--scale X`, `--strand +\|-`, `--split`, `--5p`, `--3p` and `--max-depth N` (capped into the last bin) are also supported.</li><li>Output columns follow bedtools.</li></ul>

<a id="d70"></a>**D70** `shift --by N` takes a signed N. <ul><li>`--pct` makes N a fraction of the feature's length.</li><li>`-s` negates the shift on `-` strand records, treating unknown strand as `+`.</li><li>Output is clipped as `slop` clips it: at 0, and at the chromosome end with `-g`.</li><li>The transform order warning (P1 rule) applies.</li></ul>

<a id="d71"></a>**D71** Filter expressions for `vcf filter --include EXPR` / `--exclude EXPR` (and `vcf stats`/`vcf extract`) use the grammar in P2a Task 13: a supported subset of bcftools `-i`/`-e`. <ul><li>Semantics follow bcftools for every supported construct. A `FMT/` comparison holds when **any** sample satisfies it.</li><li>A comparison against a missing value is false. Only `!=` with a missing value is true, matching bcftools.</li><li>Unsupported functions or fields are usage errors naming the token, with a hint.</li><li>Expressions are evaluated in pipeline step 4, ANDed with the other site filters and before `--thin`.</li></ul>

<a id="d72"></a>**D72** `vcf stats IN --out-prefix P [stat flags]` writes `P.<ext>` for each statistic requested, with vcftools' file extensions and column names (P2a Task 15 table). `--summary` writes `P.summary.txt`, and `--json` writes `P.summary.json`. Every `vcf filter` selection option applies first, through the same pipeline code, in one pass.

<a id="d73"></a>**D73** `vcf extract`: <ul><li>`--info KEYS` writes TSV with columns `CHROM POS ID REF ALT KEY…`; a missing value is `.` and a flag is `1`/`0`.</li><li>`--format KEYS --layout wide` writes one row per site with `<sample>:<KEY>` columns. `--layout long` writes one row per site and sample, as `CHROM POS ID REF ALT SAMPLE KEY…`.</li><li>`--genotype-matrix 012` writes vcftools' `P.012`, `P.012.indv` and `P.012.pos`. A cell holds the count of non-reference alleles, and `-1` when missing.</li></ul>

<a id="d74"></a>**D74** `vcf concat FILES…` writes the inputs one after another. <ul><li>Samples must be identical, in the same order.</li><li>Headers must be compatible, by P1's multi-VCF rule: identical INFO, FILTER, FORMAT, ALT and contig definitions, with PASS implicit.</li><li>Within the chromosome table, the last record of file *i* must sort at or before the first record of file *i+1*. Otherwise it is an error with a `gloci sort` hint.</li><li>`--naive` needs BGZF inputs with byte-identical headers. It copies the BGZF blocks after each file's header blocks without recompressing them, and drops every EOF marker except the last.</li></ul>

<a id="d75"></a>**D75** `--region`/`--regions-file` on the relation commands restrict **A** to records overlapping the regions, with view semantics (`--inclusive-points` honoured). An indexed A is read through its index. B is read normally, or through its index for the same regions widened by the window or `--max-distance`.

<a id="d76"></a>**D76** Per-chromosome parallelism for plain seekable files. An uncompressed BED/TSV/VCF that is a regular file gets one memchr scan that records each chromosome's byte range and checks that chromosomes are contiguous. Workers then read those byte ranges through the P1 per-chromosome driver. It applies when every input is either indexed or a plain seekable file, and output stays byte-identical to streaming. At `-t 1` gloci streams.

<a id="d77"></a>**D77** The spec §8.3 stage-2 parse/format worker pools are deferred to P3, unless the P2a benchmarks miss a target.

<a id="d78"></a>**D78** Native BCF genotype encoding: gloci writes the BCF FORMAT `GT` field itself, with the int8/int16 widths and end-of-vector padding for mixed ploidy. That lifts P1's `#bcf-mixed-ploidy-missing` limitation, so that docs/differences.md section and its pin are removed.

<a id="d80"></a>**D80** **Publishing (amends D59). [revised 2026-11-10: owner: "i do not want this published in pypi just yet"]** <ul><li>A `v*` tag builds and smoke-tests the archives (with man pages and completions), wheels and sdist, and attaches them all, with `SHA256SUMS`, to a GitHub Release. <a id="d81"></a>**D81** **One version** across the crates, the Python package, the conda packages, the tag and `--version`. <ul><li>Semver; before 1.0, a breaking change bumps the minor.</li><li>The first release is **0.2.0**.</li><li>`CHANGELOG.md` uses the Keep a Changelog format, and the release notes are the version's section.</li></ul>

<a id="d82"></a>**D82** **crates.io:** publish core, io, engine, vcf, ops and `gloci`, so `cargo install gloci` works. <ul><li>The internal crates say "no stable API" (§2).</li><li>The genome tables move into `crates/gloci-io/data/genomes/`. <a id="d83"></a>**D83** **Python reuses the CLI wiring** through `gloci::embed`. Defaults, validation and messages are then identical, instead of being re-implemented and drifting. gloci-py holds no command logic.

<a id="d84"></a>**D84** **In-memory endpoints** use names that start with `"\0gloci:"`. No path contains NUL, so they can't collide with real files. <ul><li>They are read or written once, like stdin, and are never indexed.</li><li>Messages use their display name: `<list>`, `<generator>`, `<pyarrow.Table>`, `f.name`, or `<intersect output>`.</li></ul>

<a id="d85"></a>**D85** **Pipelines are immutable and lazy.** <ul><li>Each step validates its kwargs when it is called (kwargs → argv → clap).</li><li>Terminals run each step on a thread, joined to the next by 4 × 1 MiB pipes.</li><li>The output equals the shell pipeline that `cli()` prints.</li><li>The earliest step whose error isn't a broken pipe or an "upstream step failed" is the one reported.</li><li>A consumer that stops early (`break`) ends the steps quietly.</li></ul>

<a id="d86"></a>**D86** **Kwargs.** <ul><li>A kwarg is the long flag name with `-`→`_`, or any one-letter short flag (for example `f`, `F`, `s`, `S`, `b`, `g`).</li><li>`True` means the flag is present; `False`/`None` mean it is absent; a list repeats the flag; any other value is `str()`.</li><li>Non-input positionals are kwargs named by their clap id.</li><li>Reserved on steps: output/format/index/compression/threads (these go to terminals), quiet/verbose (logger level), and the bound input.</li><li>Messages say `flag=` rather than `--flag`.</li></ul>

<a id="d87"></a>**D87** **API** (amended in P2b Task 4's follow-up, 2026-11-12: every P3 command is placed, and `UNBOUND` is empty). <ul><li>Sources: `gloci.open(src, *, format=None)`, `gloci.windows(**kw)` and `gloci.random(**kw)`.</li><li>One step method per stream command (P2b Task 4 `BINDINGS`), named by its path joined with `_` (`vcf_filter`, `pair_intersect`, `stats_jaccard`). The pipeline is the input:<ul><li>as `-a`: `intersect`, `subtract`, `closest`, `map`, `coverage`, `pair_intersect`, `pair_pair`, `stats_jaccard`, `stats_fisher` and `stats_reldist` (the summary table comes back through `to_bytes()` and the table terminals);</li><li>as the inputs of an n-ary command, which takes extra positional sources: `merge`, `partition`, `complement`, `sort`, `vcf_concat`, `vcf_merge`, `cat`, `depth` and `samples`;</li><li>as the one positional: `view`, `convert`, `slop`, `flank`, `shift`, `cluster`, `spacing`, `groupby`, `genomecov`, `vcf_filter`, `vcf_extract`, `vcf_split`, `vcf_norm`, `vcf_annotate`, `getfasta` and `nuc` (with `fasta=`), `sample`, `shuffle`, `faidx` (with `regions=`), `dict`, `flagstat`, `idxstats`, `head`, and `bedcov` (with `files=` for the BAMs);</li><li>as a flag: `maskfasta` (`--fasta`, with `b=` for the masks) and `windows` (`-i`);</li><li>after another positional: `reheader`, whose input follows the required `header=`.</li></ul>`b=` takes any source or a list of them, including Pipelines. Visible aliases (`diff_indv_map=`) are kwargs too.</li><li>Terminals are the spec's `save`, `to_arrow`, `to_polars`, `to_pandas`, `count` and iteration, plus `to_bytes()` (the CLI's exact stdout) and `cli()`.</li><li>Module functions: `vcf_stats`, `vcf_extract_matrix`, `vcf_compare` (prefix outputs, like `vcf_stats`) and `index`.</li><li>`genomes`, `check` and `flags` (a lookup with no input) stay CLI-only. `idxstats` and `head` gained `-o` so they can be steps.</li></ul>

<a id="d88"></a>**D88** **Sources.** <ul><li>Paths.</li><li>File objects (anything with `.read`; text is encoded as UTF-8).</li><li>Iterables of `str` lines, `gloci.Record`s, or tuples (tab-joined `str()` values, with `None` written as `.`).</li><li>Objects with `__arrow_c_stream__`: integer `chrom start end` columns come first, other nulls become `.`, and a null coordinate or a tab is a `DataError` that names the column and row.</li></ul>`.line` is the 1-based item or row number.

<a id="d89"></a>**D89** **Outputs.** <ul><li>Iteration yields `gloci.Record`s whose coordinates come from re-reading the output with gloci's readers. Unrecognised output gives `None` coordinates.</li><li>`to_arrow()` builds the whole table in memory:<ul><li>`start`/`end` are int64;</li><li>VCF columns are `pos id ref alt qual filter info format <samples>`; GFF columns are `source feature score strand frame attributes`;</li><li>other columns are named by a `#` header line, else `col<N>`; `names=` overrides.</li></ul></li><li>Column types are inferred: int64, then float64, then string.</li><li>Arrow is handed over through the PyCapsule interface. pyarrow, polars and pandas are optional extras, and a missing one raises an `ImportError` that names the extra.</li></ul>

<a id="d90"></a>**D90** **Exceptions** follow §8.5. <ul><li>`UnsortedError` adds `.records`, `.lines` and `.hint`.</li><li>`str(exc)` is the CLI's message without `error: `.</li><li>A panic raises `GlociError` with the internal-error text.</li><li>Exceptions from user sources propagate unchanged.</li></ul>

<a id="d91"></a>**D91** **Runtime.** <ul><li>A driver loop holds the GIL only to pump sources (≤ 1 MiB each), forward logs to the logger `gloci` and check signals. It releases the GIL for waits of ≤ 50 ms.</li><li>Cancellation is a per-run `gloci_io::cancel::RunToken` (amended in P2b Task 3, fix round 1). The host makes one token per run and enters it (`RunGuard::enter`) on the thread that calls P2b Task 4 `execute`, which installs it on every thread of the run (its rayon pool's workers included); the run's error is judged under it (`classify`, or `classify_under` on another thread). P2b Task 5 `StageSet` owns it, so `StageSet::cancel()` is `token.cancel()`. Readers, outputs, sorters and pools capture the thread's token when they are built, and threads a run spawns enter it at their start. `KeyboardInterrupt` calls it, which makes that run's reads and writes fail (reported as `Cancelled`), removes partial output files and re-raises; other runs are unaffected, and there is no global flag to clear.</li><li>Each run gets its own rayon pool.</li><li>The CLI's signal and panic handlers are never installed.</li><li>`[profile.release-py]` sets `panic = "unwind"`.</li></ul>

<a id="d92"></a>**D92** **Wheels:** <ul><li>abi3 for CPython ≥ 3.10;</li><li>manylinux2014 (glibc 2.17) x86_64 and aarch64, and macOS arm64 (11.0);</li><li>an sdist elsewhere (needs Rust ≥ 1.91);</li><li>on Windows, `compile_error!` names WSL.</li></ul>

<a id="d93"></a>**D93** **Bioconda has two recipes.** <ul><li>`gloci` is the CLI. It builds from the tag tarball, has no run requirements, installs man pages and completions, and targets linux-64, linux-aarch64 and osx-arm64.</li><li>`py-gloci` is the library. It builds from the PyPI sdist and ships no `bin/gloci`.</li></ul>The `gloci` name stays with the CLI (§3).

<a id="d94"></a>**D94** **The book** is in `docs/book/`. <ul><li>It includes `migration.md`, `differences.md`, `CHANGELOG.md` and the gloci-py `README.md` (which is also the PyPI page).</li><li>The command reference and `SUMMARY.md` are generated and not committed.</li><li>PRs build the book; tags deploy it to Pages.</li></ul>

<a id="d95"></a>**D95** **Paper datasets** are pinned in `xtask/bench/datasets.toml` with provider checksums and `paper = true`. <ul><li>`[[derived]]` inputs are made by a command in the bench image and checked by sha256.</li><li>`paper/fetch-datasets.sh` is generated and committed.</li><li>CI never fetches any of these.</li></ul>

<a id="d96"></a>**D96** **The paper benchmark.** <ul><li>Real-data cases are in `xtask/paper/bench.toml`.</li><li>They use the existing runner and refer to nightly cases by name.</li><li>Every bench run records peak RSS with GNU `time`.</li><li>The Python benchmark has one binding target, `gloci-py < pybedtools`. polars-bio, PyRanges v1 and bioframe are yardsticks.</li></ul>

<a id="d97"></a>**D97** **Concordance.** <ul><li>`n_matching` is the multiset intersection of record lines (positional for `numeric`).</li><li>`match_rate = n_matching / max(n_gloci, n_reference)`, or 1.0 when both sides are empty.</li><li>Runs: a *default* run uses gloci's defaults, and a *compat* run adds `compat` flags.</li><li>A rate below 1.0 needs anchors: `expected_difference` for default runs, `compat_difference` for compat runs. Each anchor must exist in `docs/differences.md` and be pinned by a golden.</li><li>An unanchored mismatch fails, and is resolved through a minimal diff case.</li></ul>

<a id="d98"></a>**D98** **`cargo xtask paper`.** <ul><li>It regenerates `paper/tables/` and `paper/numbers.{json,tex}` from the newest `paper/results/<v>/`, purely and deterministically.</li><li>Subcommands: `fetch`, `run`, `bundle`.</li><li>`run` snapshots repository facts into `repo-snapshot.json`.</li><li>Zenodo gets the software from GitHub releases through its integration, which reads `CITATION.cff`, and the evidence through a deterministic bundle the owner uploads.</li></ul>

## P3a Sequence and alignment I/O

D99–D124, from the plan "Decisions this plan adds" table.

<a id="d99"></a>**D99** **Libraries.** noodles-sam 0.93, -bam 0.98, -cram 0.102 and -fasta 0.68 are the latest releases. They pin the locked noodles-bgzf 0.52, -csi 0.62 and -core 0.21, and rust 1.91, and they are pure Rust, CRAM 3.1 codecs included. rust-htslib is excluded by §8.4. <ul><li>BAM is decoded by hand, like BCF.</li><li>noodles handles the SAM header, BAM↔SAM, CRAM, and BAI/CSI/CRAI/FAI/GZI I/O.</li><li>noodles-fasta's `IndexedReader` is not used, because it chooses BGZF by extension (against §5.1).</li></ul>

<a id="d100"></a>**D100** **Formats.** <ul><li>Detection by content:<ul><li>BAM: a BGZF stream that decompresses to `BAM\1`;</li><li>CRAM: `CRAM` with major version 2 or 3; 4 is an error;</li><li>SAM: an `@HD/@SQ/@RG/@PG/@CO` + TAB line, or ≥ 11 tab fields with integer fields 2, 4, 5, 8 and 9;</li><li>FASTA: a leading `>`;</li><li>PSL and RepeatMasker: their header, or their column shape.</li></ul></li><li>`--format` adds `bam`, `cram`, `sam`, `psl` and `rmsk`.</li><li>Only `intersect`, `coverage`, `genomecov`, `convert`, `view`, `index`, `sort` and `cat` read alignments. Elsewhere: `x.bam is BAM; this command does not read alignments (intersect, coverage, genomecov, convert, view, index, sort and cat do); convert it to BED first: gloci convert x.bam -o x.bed` (exit 2). In `gloci merge`, the message adds `to merge sorted alignment files as samtools merge does, use: gloci sort -m` (D122).</li><li>PSL and RepeatMasker are read by `convert` only. FASTA is never an interval input.</li><li>SAM is never split by D76.</li><li>Output: `.bam`, `.sam`, and `.fa`/`.fasta`/`.fna` (`.gz` = BGZF), or `-O bam\|sam\|fasta\|fasta.gz`. `.cram` is a usage error suggesting `samtools view -C`.</li></ul>

<a id="d101"></a>**D101** **An alignment as an interval.** <ul><li>The span is `[pos, pos + reflen)`, with reflen = the `M D N = X` lengths, and at least 1 for a mapped read with no reference ops (htslib's `bam_endpos`).</li><li>Clips never widen it. The strand is `-` for flag `0x10`, else `+`.</li><li>Unmapped reads (`0x4`, placed or not) are skipped by every interval command, counted at `-v`. bedtools `intersect -v` writes them: `#unmapped-reads`. The record-preserving commands keep every record (D120).</li><li>More than 65,535 ops come from `CG:B:I`.</li><li>A read past its reference's `LN` (chrM wrap) is cut at `LN`, with one warning per input. bedtools `genomecov` clips the same way.</li><li>Errors name `record N of CHROM`, counted per chromosome as the indexed reader counts, so every `-t` reports one place. SAM errors name the line.</li></ul>

<a id="d102"></a>**D102** **Read filters** (the spec had none): `--min-mapq N`, `--require-flags FLAGS` and `--exclude-flags FLAGS`. <ul><li>FLAGS is a number or comma-separated samtools names.</li><li>The filters apply to every alignment input first.</li><li>The defaults filter nothing, as bedtools. `--exclude-flags 0x704` gives samtools `depth` and mosdepth semantics.</li><li>Counts are reported at `-v`.</li></ul>

<a id="d103"></a>**D103** **Header order.** <ul><li>An alignment header's `@SQ` order is a declared order, like a VCF header in §4.5 rule 2 (a spec gap). The first header in input order wins, closed. `OrderSource::AlignmentHeader(path)` hints `gloci sort b.bed -g x.bam`.</li><li>An out-of-order alignment hints `gloci sort x.bam -o x.sorted.bam` (naming `SO:queryname` when declared), or `--sort` (D124). `--unsorted` holds B alignments in memory.</li><li>Reference id → chromosome id is a vector built once.</li><li>`--chrom-map` renames the binary reference list, `@SQ SN:`, and SAM `RNAME`/`RNEXT`.</li><li>`-g` also takes a CRAM.</li></ul>

<a id="d104"></a>**D104** **Alignments in output.** <ul><li>`intersect --mode any\|none` and `view` write alignments: BAM for a BAM or CRAM A, SAM for a SAM A, or as `-o`/`-O` choose. Asking for BED is a usage error suggesting `… -O bam \| gloci convert - -o x.bed` (D18).</li><li>Where a command prints an alignment's columns (pairs, count, `coverage`, B columns), it prints the BED6 line `convert` writes. bedtools prints BED12 with `0,0,0` and trailing commas: `#bam-as-bed-columns`.</li><li>`--mode clip` of an alignment is a usage error.</li><li>Output gets `@PG ID:gloci[.N] PN:gloci PP:… VN:… CL:…` (samtools' id rule).</li></ul>

<a id="d105"></a>**D105** **Blocks.** <ul><li>`--split` uses the reference segments between `N` ops; `D` stays inside (bedtools `intersect`/`coverage`/`bamtobed -split`).</li><li>`--split-deletions` also cuts at `D` (bamtobed `-splitD`), with or without `--split`. It is a usage error with no alignment input.</li><li>Empty blocks are dropped; with none left, the span is the block.</li><li>The rule is one for every command. So `genomecov` counts deleted bases, unlike bedtools `-ibam` (which cuts at `D` unless `-ignoreD`): `#bam-genomecov-deletions`. Parity is `--split-deletions`.</li></ul>

<a id="d106"></a>**D106** **`convert` of alignments** (bamtobed). <ul><li>Default BED6: `RNAME start end QNAME[/1\|/2] MAPQ strand`.</li><li>`--bed12`: thick = span; `--color R,G,B`, default `255,0,0`.</li><li>`--blocks` is `-split`; `--blocks --split-deletions` is `-splitD`.</li><li>`--score-tag TAG` (`-tag`; `-ed` = `NM`). A read missing the tag is a data error.</li><li>`--cigar` (`-cigar`) on BED6 only.</li><li>Input order is kept and unmapped reads are skipped.</li><li>bamtobed's extra column under `-split -tag` is not copied: `#bamtobed-split-tag`.</li></ul>

<a id="d107"></a>**D107** **Alignment indexes.** <ul><li>`gloci index x.bam` writes `.bai`, or `.csi` with `--csi` or when an `LN` exceeds 2^29.</li><li>Spans are htslib's. A placed unmapped read is indexed at `[pos, pos+1)` in the metadata counts, and unplaced reads go to `n_no_coor`.</li><li>gloci finds `x.bam.bai`, `x.bai`, `x.bam.csi`, `x.cram.crai` and `x.crai`. Stale ones warn (D26).</li><li>`--write-index` on BAM output works. On SAM output, and `gloci index` of a SAM, it is a usage error suggesting `gloci view x.sam -o x.bam`.</li><li>samtools and gloci must read each other's indexes with identical query results.</li></ul>

<a id="d108"></a>**D108** **FASTA.** <ul><li>Random access needs `.fai`, plus `.gzi` for BGZF. A missing index is a usage error with the exact `gloci index FILE` command; gloci never builds one implicitly (bedtools does). Plain gzip is an error with a `bgzip` recipe.</li><li>`gloci index` writes `.fai`/`.gzi` byte-identical to samtools/htslib: first-word names, equal line lengths (else an error naming the line), CRLF allowed.</li><li>Each fetch checks the line ends against `.fai` (else `does not match; rebuild it: gloci index ref.fa`) and streams chunks of ≤ 1 MiB, forwards or backwards.</li><li>`-g ref.fa` reads its `.fai`.</li></ul>

<a id="d109"></a>**D109** **The CRAM reference** is `--reference FASTA` only (bedtools `--cram-ref`): no `REF_PATH`, no cache directory, no network. <ul><li>Given one, each `@SQ` in the `.fai` must match its `LN`, else an error before any record.</li><li>A container that needs reference bases the FASTA lacks, or with no `--reference`: `x.cram needs the reference sequence of chr7 (M5 …, UR …) to decode its reads; pass it with --reference FASTA`.</li><li>A slice MD5 mismatch: `the sequence chr1 in ref.fa does not match the one x.cram was made with (chr1:10,001-20,000)`.</li><li>gloci's repository adapter never returns `None` (a missing name is `Some(Err)`), and slice reference ids are checked first. That keeps noodles' `expect`s unreachable.</li><li>gloci builds `.crai` itself: noodles' `fs::index` decodes multi-reference slices with an empty repository and can `todo!()`.</li><li>Each decoder clears its repository when the reference id changes, so it holds ≤ 1 sequence; per-chromosome runs hold ≤ threads.</li><li>Records are transcoded to BAM bytes.</li><li>`--reference` without a CRAM warns.</li></ul>

<a id="d110"></a>**D110** **CRAM decode pool.** Containers are read in order and decoded on ≤ threads workers, ≤ 2 × threads in flight, and released in order: the CRAM analogue of the §8.3 BGZF pool. Other D77 pools stay deferred unless P3a Task 18 misses a target.

<a id="d111"></a>**D111** **`getfasta --fasta REF FILE`** <ul><li>Output is in input order, one line per sequence.</li><li>The header is `chrom:start-end` (0-based start, as bedtools). `--name` gives `name::chrom:start-end`; `--name-only` gives `name`.</li><li>`-s` appends `(+)`/`(-)`/`(.)` and reverse-complements `-` with bedtools' IUPAC-aware, case-keeping table. `--rna` writes U.</li><li>`--split` joins BED12 blocks. `--tab` writes `header TAB seq`; `--bed-out` writes the record, then the sequence.</li><li>A record outside the FASTA is a data error (bedtools skips it: `#getfasta-outside-fasta`); `--skip-invalid` skips and counts. Points are skipped with one count warning.</li><li>`--chrom-map` renames the intervals only. VCF follows `--vcf-span`. There is no `-fullHeader`.</li></ul>

<a id="d112"></a>**D112** **`nuc --fasta REF FILE`** <ul><li>TSV: the record's columns, then `pct_at pct_gc num_A num_C num_G num_T num_N num_oth seq_len`, then `seq` (`--seq`) and the pattern count (`--pattern P`).</li><li>bedtools' header line comes first: `#1_usercol … K_usercol K+1_pct_at …`, with K from the first record. An empty input has no header.</li><li>Counts are case-insensitive, `U` counts as T, and anything else is other.</li><li>`%` is computed in f32 and printed with 6 decimals, as bedtools prints it.</li><li>`-s` reverse-complements `-` records. Pattern matches overlap and are case-sensitive unless `--ignore-case` (`-C`).</li><li>Errors as `getfasta`.</li></ul>

<a id="d113"></a>**D113** **`maskfasta --fasta IN -b MASK… [-o OUT]`** <ul><li>The FASTA (any compression, no index) is streamed. Masked bases become `--mask-char C` (default `N`) or lowercase (`--soft`).</li><li>Headers and line breaks are kept exactly. bedtools re-wraps to the first line's width and drops descriptions: `#maskfasta-layout`, `#maskfasta-header`.</li><li>Masks (any order) are merged per chromosome. Absent chromosomes get one warning. A mask past its sequence's end is a data error (`#maskfasta-past-end`).</li><li>`.fa.gz` output is BGZF, and `--write-index` writes `.fai`/`.gzi`.</li></ul>

<a id="d114"></a>**D114** **PSL and RepeatMasker → BED** (convert only; this plan counts them as alignment and sequence I/O, so they are in P3a). PSL spans `[tStart, tEnd)` on `tName`; RepeatMasker spans `[begin-1, end)`, with strand `C` = `-`. Columns follow bedops 2.4.41 `psl2bed`/`rmsk2bed`, pinned against `convert2bed --do-not-sort`. Input order is kept.

<a id="d115"></a>**D115** **Slim records.** When a command never writes an input's alignments (every B; A outside `--mode any\|none`/`view`), the reader keeps only the fixed fields, the name, the resolved CIGAR and the `--score-tag` tag. `AlignOptions.full_records` disables this. A slim record never reaches a writer (debug assertion).

<a id="d116"></a>**D116** **`view` on alignments:** BAM↔SAM and CRAM→BAM/SAM, writing every record, unmapped included (D120); region queries through the index or by scan, with §4.3 on the D101 span (a placed unmapped read spans `[pos, pos+1)`, as samtools finds it); `--header-only`; `--no-header` for SAM; the D102 filters. It is not `samtools view`.

<a id="d117"></a>**D117** **Alignment `genomecov`.** <ul><li>`-g` defaults to the header's lengths, with empty chromosomes in header order (`#genomecov-chrom-order`).</li><li>`--5p`/`--3p` take the first/last aligned base by strand, as bedtools.</li><li>An indexed input at `-t` > 1 runs per chromosome, with `genome` rows summed and output identical to `-t 1`.</li><li>`-pc`, `-fs` and `-du` are not planned: no §7.3 flag, and a §2 non-goal.</li></ul>

<a id="d118"></a>**D118** **Tools and normalisation.** <ul><li>`gloci-diff` adds `samtools=1.21`; the bench image adds `samtools=1.21` and `mosdepth=0.3.10` (both on htslib 1.21).</li><li>`observe()` drops `@PG\tID:gloci` lines, and references use `samtools view --no-PG`.</li><li>New compare mode `bam`: decompress both, then compare the header text minus `@PG`, the references, and the record bytes.</li></ul>

<a id="d119"></a>**D119** **Binary fixtures** live in `xtask/diff/inputs/{aln,fa}/`, each next to its SAM/FASTA source. `make-<set>.sh` rebuilds them in `gloci-diff:p0` (`--no-PG`, one thread, level 6). A test checks that each BAM decodes to its source.

<a id="d120"></a>**D120** **Every-record alignment source.** <ul><li>`AlnSource` yields every record of a BAM, SAM or CRAM in file order, unmapped included, with the D102 filters when given.</li><li>Records come in the reader's raw layout: BAM bytes for BAM and CRAM, the line for SAM.</li><li>`view`, `sort`, `sort -m` and `cat` use it, and so will P3c's per-record commands. Interval commands keep `RecordReader` (D101).</li><li>Sort and merge encode SAM records to BAM bytes once, at read.</li></ul>

<a id="d121"></a>**D121** **`gloci sort` for alignments** follows samtools 1.21 `bam_sort.c` exactly. <ul><li>Coordinate (the default): `(tid, with -1 as n_ref so unplaced reads go last; pos+1; the reverse-strand bit; input order)`. samtools' LSD radix sort is stable and its run merge breaks ties by run, then index, so this is samtools' total order.</li><li>`-n`: `(strnum_cmp(QNAME), flag rank, input order)`, with samtools' `strnum_cmp` ported byte for byte: unsigned bytes, digit runs compared as numbers after leading zeros are skipped, so `r01` equals `r1`. The flag rank is `((f&0xC0)<<8)\|((f&0x100)<<3)\|((f&0x800)>>3)`: neither mate, then READ1, then READ2; within each, primary, then supplementary, then secondary.</li><li>`-N`: as `-n`, but QNAMEs compare as bytes (`strcmp`). `-n`/`-N` are the owner's §10 flags; `windows -n COUNT` keeps its meaning (an owner exception, like `groupby -g`). The long forms are `--by-name` and `--by-name-bytes`.</li><li>`@HD`, as `sam_hdr_update_hd`: `SO` replaced in place, or appended. Coordinate removes `SS`; `-n` sets `SS:queryname:natural`; `-N` sets `SS:queryname:lexicographical`. `GO` is removed. With no `@HD`, `@HD VN:1.6 SO:…` comes first. `@PG` follows D104.</li><li>One input (BAM, SAM or CRAM). CRAM writes BAM. `-o x.sam`/`-O sam` writes SAM.</li><li>`--write-index` works on coordinate output only (`.bai`, or `.csi` per D107).</li><li>`--check` checks the chosen order.</li><li>`-g`, `--full-key`, `--unique` and `--duplicates` with alignments are usage errors. The order is the header's.</li><li>The external sorter takes an `Order` (interval, coordinate, name natural, name bytes). Spill runs hold raw records with their `block_size`.</li></ul>

<a id="d122"></a>**D122** **Alignment merge is `gloci sort -m`.** `-m` already means "merge sorted inputs" in gloci (bedops `-u`, `sort -m`). `gloci merge` keeps its interval meaning, one name for one meaning (§2), and its alignment message points to `sort -m`. <ul><li>The keys are D121's (`-n`/`-N` select name order). Ties go to input file order, then record order (samtools' `heap_lt`).</li><li>Each input is order-checked as it is read. An input whose `@HD SO`/`SS` contradicts the mode is an error up front. An absent `SS` is accepted.</li><li>`@SQ` lists must be identical (names, `LN`, order), else an error naming the first difference. samtools appends unknown `@SQ` lines and only warns when coordinate order is lost: `#alignment-merge-sq`.</li><li>`@HD` comes from the first input, with `SO`/`SS` set as D121.</li><li>`@RG`/`@PG` with the same ID are combined: an identical line is kept once (samtools `-c -p`). A same-ID `@RG` with a different line is an error naming both lines (samtools `-c` keeps the first): `#alignment-merge-rg`. A same-ID `@PG` keeps the first. samtools' default suffixes colliding IDs with `lrand48` seeded by the clock, which cannot be reproduced. Goldens use `samtools merge -c -p`.</li><li>`@CO` lines come from every input, in order.</li><li>`-r` (an RG from the file name) is not supported.</li></ul>

<a id="d123"></a>**D123** **`gloci cat`** (samtools `cat`) joins BAMs byte-level. Its meaning is `vcf concat --naive`'s, not `vcf concat`'s checked join, so it takes samtools' name. <ul><li>The header is the first input's, plus each later input's `@RG` lines with new IDs (samtools).</li><li>Every input's `@SQ` list must equal the first's. samtools does not check, so records silently point at the wrong reference: `#alignment-cat-sq`.</li><li>Each later file's block holding its header end is recompressed from there; every later block is copied verbatim; EOF markers are dropped and one is written at the end. The format-neutral copy loop moves from `gloci-vcf/src/concat.rs` into `gloci-io` and serves both.</li><li>No order check. `@HD` is kept as samtools keeps it.</li><li>BAM only. CRAM is refused, suggesting `samtools cat`; SAM is refused, suggesting `gloci view x.sam -o x.bam`.</li></ul>

<a id="d124"></a>**D124** **`--sort` with alignments** (amends D103): <ul><li>relation commands and `genomecov` sort alignment inputs with the interval sorter, like BED, into a level-1 temporary BAM (slim records allowed there), then stream;</li><li>the table is the header's, so BED inputs must follow `@SQ` order or be sorted too;</li><li>memory stays within `--max-mem`.</li></ul>

<a id="d143"></a>**D143** **The random stream.** `rand_chacha` 0.10 `ChaCha8Rng`, used only through `next_u64`, `set_stream` and `set_word_pos`. Key = `seed.to_le_bytes()` then 24 zero bytes; stream = the unit of work (D144). Draws are gloci's own: `below(n)` = Lemire's multiply-shift with rejection (`m = x·n` as u128; if `(m as u64) < n`, `t = n.wrapping_neg() % n` and redraw while `(m as u64) < t`; return `m >> 64`); `unit()` = `(x >> 11) × 2⁻⁵³`; `coin()` = top bit. A known-answer test pins the first outputs; changing them is a breaking change for the release notes. `--seed N` is a u64; without it gloci seeds from `RandomState` and warns `no --seed given; using --seed N (pass it to reproduce this output)`, which is how §7.3's "`--seed` required for reproducibility" is read.

<a id="d144"></a>**D144** **What randomness guarantees.** Same seed, input and options → the same bytes at every `--threads`, on every platform, in every release unless its notes say the stream changed. Units: `random` interval *i* uses stream *i*; `shuffle` data record *j* uses stream *j* (retries included); `sample` uses stream 0 with record *j*'s key at word 2(*j*−1). Distributions are exact (no modulo or cast bias) and defined in D150–D153. Not guaranteed: bedtools' output for the same seed (`#rng-stream`), or gloci's under other options. Tested by the known-answer test, χ² uniformity at fixed seeds (deterministic), constraint property tests and `-t` determinism.

<a id="d145"></a>**D145** **Numbers.** <ul><li>The reference's operation order and precision: f32 where bedtools divides in `float` (jaccard); f64 for `double`; exact u128 rationals where bedtools uses x87 `long double` (fisher's estimate; a 1-unit golden difference pins `#fisher-estimate-exact`). vcftools' 32-bit products and positions are computed in u64 (`#popgen-integer-overflow`).</li><li>`lgamma`/`exp` come from `libm`; `sqrt` is IEEE-exact.</li><li>Printing goes through `gloci_core::cfmt`: `write_g(x, prec)` (`%.Pg`; C++ `<<` is precision 6), `write_e6`, `write_fixed(x, prec)` (`%.Nf`; Rust rounds ties to even, as glibc). NaN prints `nan`, infinities `inf`/`-inf`; fixed reference strings (fisher's `-nan`) are printed as such. A golden where the reference prints `-nan` for an arithmetic NaN pins `#nan-sign` (a NaN's sign differs between x86 and Arm; gloci never prints it).</li><li>Each statistic has an oracle test from the published formula (hypergeometric Fisher; Nei–Li π; Tajima 1989; Weir–Cockerham 1984; Pearson r², Lewontin D′; Yang 2010; Manichaikul 2010), never from the port.</li></ul>

<a id="d146"></a>**D146** **BEDPE** (§5.1). <ul><li>Never detected, since `intersect --mode pairs` of two BED3 files has its shape. `pair-intersect -a`, `pair-pair -a/-b` read BEDPE; `shuffle --format bedpe` opts in; `--format bedpe` elsewhere is exit 2 naming those commands. An input detected as VCF, BCF, GFF or alignments is exit 2 (alignments: `gloci convert x.bam --bedpe`).</li><li>Columns `chrom1 start1 end1 chrom2 start2 end2 [name score strand1 strand2 extra…]`: 6, 7, 8 or ≥ 10 per line (9 is an error, as bedtools); lines may differ. Leading `#`/`track`/`browser` lines are headers; CRLF tolerated.</li><li>chrom `.` = an absent end (`. -1 -1`): integer coordinates, ignored, overlaps nothing. Otherwise non-negative, `start ≤ end`, points allowed. Strands `+ - .`; none or `.` is unknown and never matches `-s`/`-S`.</li><li>Records are written unchanged; `--chrom-map` rewrites both chrom columns; `--skip-invalid` applies.</li><li>Output `.bedpe[.gz]` / `-O bedpe\|bedpe.gz` (BGZF for `.gz`); `--write-index` is exit 2 suggesting `gloci index -s 1 -b 2 -e 3 --zero-based x.bedpe.gz`.</li></ul>

<a id="d147"></a>**D147** **`stats jaccard -a A -b B`.** Each input is merged as `gloci merge` does (overlapping and bookended; per strand with `-s`). Intersection = Σ overlap bases of merged A × merged B pairs accepted by §4.3 (`-f -F -r -e --min-bases -s -S --inclusive-points`, measured on merged intervals); n_intersections = those pairs; union = Σ merged A + Σ merged B − intersection, both inputs read to the end. Output `intersection\tunion\tjaccard\tn_intersections` and one row, jaccard = `I as f32 / U as f32` printed `%g`. Sorted inputs, order-checked; `--sort`; VCF per `--vcf-span`; points cover no bases but count as intersections.

<a id="d148"></a>**D148** **`stats fisher -a A -b B -g G`.** <ul><li>Counts, unmerged (merged with `--merge-overlaps`): records nA, nB; summed lengths LA, LB; n11 = accepted pairs; both inputs read to the end. G = Σ `-g` lengths (required) minus the merged length of `--exclude BED`, which only shrinks G, as bedtools.</li><li>Table as bedtools: n12 = max(0, nA−n11), n21 = max(0, nB−n11); `n22_full = max(n11+n12+n21, ⌊G·nA·nB / (2·nA·nB + LB·nA + LA·nB)⌋)` (= `⌊G/(2 + LA/nA + LB/nB)⌋` exactly; u128, f64 on overflow); an empty A or B gives `n11+n12+n21` (C's `(long long)NaN`); n22 = max(0, n22_full − n12 − n21 − n11).</li><li>p-values: klib's `kt_fisher_exact`, operation for operation, `lbinom` on `libm::lgamma`; ratio = `(n11/n12)/(n21/n22)`.</li><li>Output is bedtools' text byte for byte: the `#` lines (`%-12lld` cells), `left\tright\ttwo-tail\tratio`, `%.5g` p-values and `%.3f` ratio or the literal `-nan`.</li></ul>

<a id="d149"></a>**D149** **`stats reldist -a A -b B [--detail]`.** Midpoints `⌊(start+end)/2⌋` in u64 (bedtools casts the sum to `int`: `#reldist-midpoint-overflow`). Per A, bedtools' `lower_bound` neighbours among B midpoints on its chromosome; A before the first, after the last, or without B is skipped; rel = 0 when a distance is 0, else `min(dl, dr)/(right − left)` in f64. Summary: bins `⌊rel·100⌋`, rows `%.2f\t%lu\t%lu\t%.3f` under `reldist\tcount\ttotal\tfraction`, ascending. `--detail`: A's record, a tab, `%.3f`, in A's order (§4.6). Sorted streaming reads each chromosome's B once; `--unsorted` loads all B midpoints.

<a id="d150"></a>**D150** **`random -g G [-l 100] [-n 1000000]`.** Valid starts on chromosome c are `0..=len_c − l`. Interval *i* draws uniformly over all valid starts (prefix sums, binary search), then `coin()` → `+`: bedtools' rejection distribution without rejection. Rows `chrom start end i l strand` in *i* order, not sorted (help says so). `l` above every length is exit 2 naming the longest chromosome (bedtools loops forever: `#random-too-long`); `-g` without lengths is exit 2.

<a id="d151"></a>**D151** **`sample FILE -n N`.** Complying records (with `--strand`, that strand; unknown never complies) are numbered *j*; key *j* = stream 0 at word 2(*j*−1); the N smallest (key, *j*) are kept, a uniform N-subset, written in input order (bedtools: reservoir order, `#sample-order`). Headers per `--header`; VCF keeps its header. Fewer than N complying records: exit 1 with the count, as bedtools, and nothing written.

<a id="d152"></a>**D152** **`shuffle FILE -g G`.** <ul><li>Allowed set = `--include` regions (else the genome) minus `--exclude`, merged per chromosome. A record of length L may go to `(c, s)` with `a ≤ s ≤ b−L` inside one allowed `[a, b)`: the whole record stays inside (bedtools only places the start in an `-incl` interval: `#shuffle-placement`).</li><li>Uniform over all placements; `--same-chrom` over the record's chromosome; `--chrom-first` picks uniformly among chromosomes with a placement, then within it. Exact: allowed intervals sorted by length (ties: chromosome rank, start) with prefix sums make the count and the *r*-th placement binary searches.</li><li>No placement: exit 1 naming file, line and length, with the fix (shrink `--exclude`, widen `--include`, or `--skip-unplaceable`, which skips, counts and lists 10); nothing written. bedtools drops the record with a message.</li><li>`--no-overlapping`: input order; a placement overlapping an earlier one is redrawn from the same stream up to `--max-tries` (1000), then is unplaceable.</li><li>Other columns and strand kept (GFF via `rewrite_coords`); VCF/BCF is exit 2 suggesting `gloci convert`; the order warning applies.</li></ul>

<a id="d153"></a>**D153** **`shuffle --format bedpe`.** A one-chromosome pair is placed as its outer span, keeping its layout; a two-chromosome pair places each end independently; absent ends stay absent. With `--exclude` both ends must avoid excluded regions (the gap may cross them, as bedtools), redrawn up to `--max-tries`. `--include`, `--same-chrom`, `--chrom-first`, `--no-overlapping` are exit 2 (bedtools ignores them).

<a id="d154"></a>**D154** **`pair-intersect -a PAIRS -b FILE [--type T]`.** <ul><li>B (BED, GFF, VCF footprints) goes into an `IntervalIndex`; A streams in any order in ≤ 2 × threads batches, queried in parallel, written in A's order. Each present end is tested under §4.3 with the end as A.</li><li>`--type`: `either` (default) A+B per hit of end 1, then end 2; `both` the same when both ends hit; `xor` one end only; `neither` A alone, no hit; `notboth` A alone with no hit, A+B with one; `ispan`/`ospan` A+B per B hitting the inner `[end1, start2)` (`[end2, start1)` when end 1 is right of end 2) or outer span; `notispan`/`notospan` A alone when nothing hits it.</li><li>Span types need both ends on one chromosome (others skipped, counted in one warning); an empty inner span hits nothing; `-s`/`-S` with them is exit 2, as bedtools.</li><li>Hits in B's input order (bedtools: bin order, `#pair-hit-order`). A+B rows are TSV (D42); `notboth`'s A-alone rows are padded with `.` (D45, `#pair-notboth-padding`); A-alone types write BEDPE.</li></ul>

<a id="d155"></a>**D155** **`pair-pair -a PAIRS -b PAIRS [--type both]`.** B's end 1 and end 2 each get an `IntervalIndex`; orientation 1 tests A1–B1 and A2–B2, orientation 2 A1–B2 and A2–B1. `both`: B with both ends hit in either orientation; `either`: any end; `neither`: A alone with no B end hit; `notboth`: A alone with no B fully hit. Each (A, B) is written once with B's line as written (bedtools prints one row per orientation, `#pair-pair-once`, and in `either` swaps B's ends when only its end 2 hit, `#pair-pair-b-columns`), in B's input order. Strand is ignored unless `-s`/`-S` (bedtools enforces strand unless `-is`, matching `.` with `.`: `#pair-unknown-strand`). `-w`/`--left`/`--right`/`--strand-window` pad B per §4.3 (D37 applies). `--require-different-names` drops B named like A (column 7); a line without a name is then a data error.

<a id="d156"></a>**D156** **`convert --bedpe`** (alignments). Reads `AlnSource` with the D102 filters in file order; `@HD SO:coordinate` is exit 2 suggesting `gloci sort -n x.bam -o x.byname.bam`. Consecutive records sharing a QNAME form a group whose primary READ1 and READ2 (`0x40`/`0x80`, not `0x900`) make the pair; secondary and supplementary records are ignored (bedtools pairs whatever is adjacent: `#bamtobed-bedpe`); a group with one primary mate warns once with a count. Ends: `RNAME start end strand` (D101) or `. -1 -1 .` when unmapped; swapped so `(chrom1, start1) ≤ (chrom2, start2)` comparing names as bytes (`.` first), unless `--mate1-first`. Name = QNAME; score = min MAPQ when both mapped, else 0, or with `--score-tag TAG` the sum over mapped ends (`NM` = `-ed`; missing on a mapped end is a data error). Conflicts with `--bed12`, `--blocks`, `--cigar`, `--color`.

<a id="d157"></a>**D157** **Parallel selection** (P2a follow-up 1 lands here: `vcf popgen`/`compare` are new consumers of the stage, and P2b's evidence suite needs §9.1's `vcf stats` target). With `--threads` > 1, `run_selection` hands batches to `threads − 1` workers, each with its own copy of the stage (expression, scratch, BCF dictionaries, masks), returning per record pass/fail, `SiteStats`, mask flags and, under shared decoding, the samples in a `PackedGenotypes` arena. The driver keeps the order guard and `--thin`, takes batches back in order (≤ 2 × workers in flight) and calls the sink in record order. Batches hold ≤ max(1, 524,288 / samples) records. The earliest failing record is reported, so errors match at every `-t`. `-t 1` keeps today's path. Every `vcf` command uses it; the other D77 pools stay deferred.

<a id="d158"></a>**D158** **`vcf popgen IN --out-prefix P`.** <ul><li>Selection first (D50), then every requested statistic in one pass through the `vcf stats` engine; files publish atomically (D72).</li><li>Files (vcftools' names and columns): `--site-pi` `.sites.pi`; `--window-pi SIZE [--window-pi-step S]` `.windowed.pi`; `--tajima-d BIN` `.Tajima.D`; `--fst-pop FILE`×≥2 `.weir.fst` + `.weir.fst.summary`, with `--fst-window-size N [--fst-window-step S]` `.windowed.weir.fst`; `--geno-r2` `.geno.ld`; `--hap-r2` `.hap.ld`; `--interchrom-geno-r2`/`--interchrom-hap-r2` `.interchrom.{geno,hap}.ld`; `--relatedness[2]` `.relatedness[2]`.</li><li>Windowed statistics and window LD need input sorted by chromosome and position (the `--snp-density` rule: `#popgen-sorted-input`). A step larger than its window is exit 2 (vcftools resets it: `#popgen-window-step`).</li><li>Options never leak between statistics: populations select no samples, and hap-r2's phase rule removes no sites from others (vcftools does both: `#popgen-independent-options`). vcftools `--het` is `vcf stats --het`.</li></ul>

<a id="d159"></a>**D159** **π and Tajima's D**, as vcftools 0.1.16. <ul><li>A site counts only when every unmasked selected sample is diploid (`SiteStats` neither `haploid` nor `polyploid`); allele counts include `./1`'s called allele.</li><li>Site π = `Σ c_a(n−c_a) / (n(n−1))` over called alleles; NaN when n < 2.</li><li>Window π: windows `[k·step+1, k·step+size]`, k from `⌈(pos−size)/step⌉` (≥ 0) to `⌈pos/step⌉−1`. Polymorphic sites add `n(n−1)` comparisons and their mismatches; the rest of the window is monomorphic at `N(N−1)`, N = 2 × selected samples. N_VARIANTS = sites with `c_ref < n`; windows without one are not printed.</li><li>Tajima's D: biallelic diploid sites; bin = `⌊POS × (1/BIN)⌋` in f64 (POS 49, BIN 49 → bin 0); n = 2 × selected samples throughout; polymorphic sites add `p(1−p)`. Rows run from the first bin with S > 0 to the chromosome's last bin, empty ones `0 nan`; BIN_START = `bin × BIN`. Constants a1…e2 in f64 (vcftools' 32-bit `n²` wraps above 32,768 samples: `#popgen-integer-overflow`).</li></ul>

<a id="d160"></a>**D160** **Weir and Cockerham Fst** (vcftools' multi-allele form). Population files: one name per line (first word, blank lines skipped), after selection. Fewer than 2 files, a file with no selected sample, or a sample in two files is exit 2 naming it (vcftools skips, divides by zero or double-counts: `#fst-populations`); unknown names warn once with a count. Per diploid site: n_i, p_ij, h_j from per-population genotype counts, then a, b, c per allele in vcftools' operation order; fst = Σa/Σ(a+b+c) over alleles where none is NaN; every diploid site gets a row (an all-missing population gives NaN). `.weir.fst.summary` = `N_SITES\tMEAN_FST\tWEIGHTED_FST` over non-NaN sites (vcftools only logs them). Windows (D159's) sum a, a+b+c, fst and count non-NaN sites; printed when Σ(a+b+c) ≠ 0 and the count > 0; written as positions pass them.

<a id="d161"></a>**D161** **LD** (biallelic sites, 3 bits per sample for genotypes and 4 for haplotypes, in 64-sample words, plus 16 bytes per site). `--geno-r2`: dosage 2/1/0 for `0/0`/het/`1/1`; missing, half-called, haploid or masked genotypes skipped; r² = cov²/(var₁var₂) over samples called at both, N_INDV. `--hap-r2`: haplotypes of phased genotypes (a haploid genotype is one haplotype, `.|1` its called one, as vcftools reads them), D, D′, r², N_CHR as `calc_hap_r2`, using only sites where every selected genotype is phased, read before masking (vcftools' implied `--phased`). A genotype of ploidy above two among the selected, unmasked samples at a biallelic site stops the run (exit 1): vcftools stops when it parses one, before its LD code could skip it, and gloci's other statistics stop the same way (`#polyploid-unused-samples` for the samples not read); a multi-allelic site is not read, as vcftools drops it before parsing. Pairs (i, j>i) on one chromosome, counted among the sites the statistic uses, with `j−i ≤ --ld-window`, `j−i ≥ max(1, --ld-window-min)`, `--ld-window-bp-min ≤ Δpos ≤ --ld-window-bp`; `--min-r2 X > 0` drops r² < X and NaN; order (i, j); a site's pairs are written when its window closes; sorted input (`#popgen-sorted-input`); a window that admits no pair is exit 2 (`#popgen-window-step`). `--interchrom-*`: every pair on different chromosomes, (i, j) order, at the end; any input order. Held sites of all LD statistics together, counted as the bytes their stores have allocated (a store grows by doubling within what is left and keeps what it took), past `--max-mem` (2G): exit 1 naming the fix (`--ld-window-bp`, `--ld-window`, `--max-mem`); vcftools spills to a temporary file (`#ld-rules`).

<a id="d162"></a>**D162** **Relatedness** (biallelic diploid sites, selected samples). `--relatedness2` (Manichaikul): per pair N_AaAa, N_AAaa, N1_Aa, N2_Aa and φ = (N_AaAa − 2·N_AAaa)/(N1_Aa + N2_Aa), every ordered pair with self, header order. `--relatedness` (Yang Ajk, unadjusted): sites with ε < f < 1−ε; per pair i < j, Σ(x_i−2f)(x_j−2f)/(2f(1−f)) over samples called at both, divided by that count; self = 1 + Σ(x²−(1+2f)x+2f²)/(2f(1−f))/count. Masked and half-missing genotypes are missing (vcftools counts masked ones in `relatedness2` and `./1` as 0 in `relatedness`: `#relatedness-genotypes`). 64-site blocks become per-sample bit masks (pair counts add popcounts); matrix rows split over scoped threads, each pair summing sites in input order, so every `-t` gives the same output.

<a id="d163"></a>**D163** **`vcf compare A B --out-prefix P`.** <ul><li>Both inputs selected (D50; `--samples` applies per file by name, a name in neither is exit 2), walked in the shared table's order (§4.5: `-g`, else A's header, else karyotype/lex), each order-checked; a chromosome in one file only is fine (vcftools stops).</li><li>`--match alleles` (default, §7.8): same CHROM and POS and a shared ALT after §4.2 trimming (`intersect --match alleles`); each A record takes the first unmatched matching B record; leftovers at the position pair as `O`, the rest are `1`/`2`. No normalisation: the same change at another POS is another site. `--match position` reproduces vcftools' walk (same POS → `B`, differing REF → `O`, `N`/`.` REF taking the other's; overlapping REF spans → `O`).</li><li>Files (all unless some are requested): `--site-overlap` `.diff.sites_in_files`, `--sample-overlap` `.diff.indv_in_files`, `--site-discordance` `.diff.sites`, `--sample-discordance` `.diff.indv`, `--discordance-matrix` `.diff.discordance_matrix`.</li><li>Samples: the union by name after `--sample-map FILE` renames B's (`--diff-indv-map`), byte order. Genotypes compare as unordered allele strings; any missing allele makes it missing (vcftools counts `./1` as called: `#compare-half-missing`). The matrix counts biallelic pairs with identical REF/ALT, skipping haploid genotypes, as vcftools.</li></ul>

<a id="d164"></a>**D164** **Fixtures and goldens.** Interval fixtures in `xtask/diff/inputs/p3b/{stats,random,pairs}/`; alignment fixtures extend P3a's `aln/` through `make-alignments.sh`; VCF fixtures beside their goldens. Random commands cannot match bedtools' stream, so their goldens are forced cases with one possible placement (which must match) and `#rng-stream` cases pinning gloci's own output (`expected_gloci`). No new compare mode.

<a id="d166"></a>**D166** **`gloci convert ALN --fastq`** (bedtools `bamtofastq`) **[owner, 2026-11-15]**, experimental as `convert`. <ul><li>Input BAM, CRAM (`--reference` as `convert` takes it) or SAM; FASTQ to `-o` (a `.fq` or `.fastq` name, `.gz` is BGZF, stdout as text) and with `--fastq2 FILE` the second mates to FILE, written atomically by the same rules. `-o` and `--fastq2` both on stdout, or the same file, interleave the ends (R1, R2, R1, R2), as bedtools' own `/dev/stdout` tip does. `--tags` is `-tags` and needs `--fastq2` (bedtools ignores it without `-fq2`). `--fastq` cannot be combined with the BED-output options of `convert`.</li><li>Without `--fastq2`, every record is written, once, in input order, under its own name: no flag filters (secondary, supplementary, unmapped, QC-fail, duplicates included; `--exclude-flags`, `--require-flags` and `--min-mapq` still apply), as bedtools. bedtools writes each of them twice: `#bamtofastq-single-twice`.</li><li>A read with `0x10` is reverse-complemented (IUPAC-aware, upper case as BAM holds it) with its qualities reversed; QUAL `*` is `!` for each base and SEQ `*` an empty read, as bedtools.</li><li>With `--fastq2`, the records of a name that are next to each other make a group: its first record, and each later one marked paired (`0x1`; with `--tags` every one). A group of two with READ1 and READ2 in either order is written as `NAME/1` and `NAME/2`; a group of one, or of two that are not READ1 and READ2, is skipped and counted in a warning, as bedtools does, and does not disturb the next name. A group of more than two is an error naming the read and `--exclude-flags 0x900`: `#bamtofastq-three-records`. An unpaired first record of the file writes no empty read: `#bamtofastq-first-unpaired`. A `SO:coordinate` header is exit 2 suggesting `gloci sort -n`: `#bamtofastq-coordinate-sorted`.</li><li>`--tags` writes each pair from its first record: its bases and qualities (reverse-complemented when `0x10`) to the end its flags give (READ2 if it is not READ1), the `R2` and `Q2` string tags as they are to the other end; when the first record is READ2 the other end is written first, as bedtools. A first record with no `R2` or `Q2` string tag is an error: `#bamtofastq-tags-missing`; the pair after an orphan is kept: `#bamtofastq-tags-orphan`.</li></ul>

<a id="d167"></a>**D167** **`gloci convert FILE --bam -g GENOME`** (bedtools `bedtobam`) **and `gloci convert FILE --format bedpe --bam -g GENOME`** (`bedpetobam`) **[owner, 2026-11-15]**, experimental as `convert`. <ul><li>BAM to `-o` (a `.bam` name; any other is exit 2 pointing at `gloci view -O sam`) or stdout, as bedtools writes it, through the alignment writer: each record is the SAM line bedtools' record reads as, encoded by the writer's SAM encoder (no second encoder), with gloci's `@PG` line (D104). `--compression-level 0` writes level-0 BGZF and is `-ubam` (bedtools 2.31.1 compresses `-ubam` output all the same).</li><li>The header is bedtools': `@HD VN:1.0 SO:unsorted`, then one `@SQ SN:… AS:… LN:…` per chromosome of `-g` in the genome's order, `AS:` being the `-g` value as given. `-g` is any genome gloci takes (built-in name, `.genome`, `.fai`, `.dict`, VCF/BCF or BAM header); one without a length, or longer than 2^31-1, is exit 2. bedtools sorts `bedpetobam`'s `@SQ` lines by name: `#bedpetobam-header-order`.</li><li>Input is read as `igv` reads it (D169): BED, GFF or VCF, every BED or GFF record with the first record's column count, a BED record one base wider on each side when zero-length (the base after it at 0, where bedtools writes position -1: `#bedtobam-zero-length-at-start`), a GFF record its feature type at `start-1`, a VCF record `REF/ALT[_ID]` over its REF bases. A BED record needs a name (BED3 is exit 1, as bedtools). A record is `NAME FLAG CHROM START+1 MAPQ (END-START)M * 0 0 * *`, FLAG 16 when the strand column is exactly `-`; `--mapq N` is `-mapq` (0 to 255, default 255).</li><li>`--bed12` (`-bed12`): the record must be valid BED12 by `convert --blocks`' rule (`#bedtobam-bed12-blocks`); each block is an `M`, each gap an `N`, adjacent blocks stay separate `M` operations and a size-0 block is `0M`, as bedtools writes them.</li><li>BEDPE is read when `--format bedpe` asks (D146: never detected; a `.bedpe` name without it is exit 2 naming the option). Each line needs a name and the first line's column count; 7 and 8 columns are read (`#bedpetobam-columns`). Two records per pair, READ1 then READ2, as bedtools: FLAG `0x1`, `0x40`/`0x80`, `0x10` for the end's own `-` strand and `0x20` for its mate's, `0x2` when both ends are on one chromosome with strand1 `+` and strand2 `-`; RNEXT/PNEXT point at the other end; TLEN is `start2 - start1` on both records on one chromosome, else 0; CIGAR `(end-start)M` (`0M` for a zero-length end, not widened). An absent end (`.`) is unmapped (`0x4`, `0x8` on its mate, CIGAR `*`, MAPQ 0), placed at its mate, or unplaced when both are absent, with TLEN 0: `#bedpetobam-absent-end`.</li><li>A chromosome `-g` lacks is exit 1 naming it and the fix (bedtools writes the record on the first reference): `#bedtobam-missing-chromosome`. A record BAM cannot hold (a name over 254 characters, a CIGAR operation of 2^28 or more, a position past 2^31) is exit 1: `#bedtobam-unrepresentable`. BAM output is compared with its `@PG` and `@CO` lines left out, as the introduction of `docs/differences.md` says.</li></ul>

## P3c samtools essentials

D125–D141, from the plan "Decisions this plan adds" table.

<a id="d125"></a>**D125** **Scope and names.** <ul><li>`idxstats`, `flagstat`, `reheader`, `faidx`, `dict`, `head`, `samples`, `flags`, `depth` and `bedcov` keep samtools' names, as `cat` does (D123): gloci has no command with those meanings.</li><li>`quickcheck` is `check --quick` (D129), because `check` already means "validate files" (§7.4).</li><li>`view -c` is `view --count`, because `-c` is `COL:OP` (§6.3).</li><li>`view -L` is the existing `--regions-file` (§6.1), which already reads through an index (D133).</li><li>samtools' short flags are not copied, because several letters already mean something else in gloci (`-c -n -i -s -a -b -r -f`). Every samtools flag maps to a long flag named in its D-row and in the migration table.</li><li>The D100 gate adds `idxstats, flagstat, check, reheader, head, samples, depth, bedcov` to the alignment readers, and `faidx, dict` to the FASTA readers.</li><li>**Not planned** (each a migration row):<ul><li>`fqidx` and `faidx --fastq`;</li><li>custom index paths (`-X`, `--fai-idx`, `--gzi-idx`);</li><li>file lists (`depth -f`, path lists on stdin);</li><li>`reheader -c` (pipe `view --header-only` instead) and `--in-place` (`-o` set to the input replaces it atomically);</li><li>`depth --incl-flags` and `-d`/`-m` (ignored by samtools);</li><li>`bedcov --max-depth` (samtools' default is no cap);</li><li>`samples -F` (repeat `--match-reference`).</li></ul></li></ul>

<a id="d126"></a>**D126** **Shared rules.** <ul><li>Per-record commands read through `AlnSource`. Only `view`, `depth` and `bedcov` take the D102 filters (and `--chrom-map`). `idxstats`, `flagstat`, `check`, `head`, `samples` and `reheader` describe the whole file and take neither.</li><li>`--column-names` writes one `#`-prefixed column-name line first (samtools `depth -H`, `bedcov -H`, `samples -h`).</li><li>Exit status is §6.4's: 1 for data errors and failed checks, 2 for usage errors. samtools exits 1 for usage errors, 2 for `bedcov` errors, and a bit mask from `quickcheck`: `#samtools-exit-codes`.</li><li>**CRAM.** Commands that decode records need `--reference` whenever a container needs reference bases (D109): the `idxstats` and `flagstat` scans, `head`, `view`, `depth` and `bedcov`. samtools decodes only the fields it needs, so its `flagstat`, `idxstats` and `view -c` read such a file without one: `#cram-counts-need-reference`. `samples`, `reheader` and `check --quick` never need a reference.</li><li>`depth` and `bedcov` inputs must have identical `@SQ` lists (names, `LN`, order), else exit 1 naming the first difference. samtools compares reference ids across files unchecked: `#depth-bedcov-same-sq`.</li></ul>

<a id="d127"></a>**D127** **`gloci idxstats FILE`.** <ul><li>Per `@SQ`: `name TAB LN TAB mapped TAB unmapped`, then `* TAB 0 TAB 0 TAB unplaced`.</li><li>A BAM with a `.bai`/`.csi` is answered from the index's metadata pseudo-bins and `n_no_coor`, without reading records.</li><li>Otherwise one warning, and every record is counted through `AlnSource`. This covers a BAM without an index (samtools also scans), a SAM, and a CRAM (a `.crai` holds no counts). The warning reads: `x.bam has no index; counting every record (index it for speed: gloci index x.bam)`.</li><li>A placed unmapped read counts as unmapped on its reference (D107).</li><li>The scan does not need grouped references. samtools' scan stops with `file is not position sorted`: `#idxstats-unsorted`.</li><li>An index lacking `n_no_coor`, or with a reference that has bins but no metadata pseudo-bin, counts as "no counts": one warning and a scan. htslib prints `0 0` for it: `#idxstats-index-without-counts`.</li><li>Stale indexes warn (D26).</li></ul>

<a id="d128"></a>**D128** **`gloci flagstat FILE [-O text\|tsv\|json] [-o PATH]`.** <ul><li>The counts follow samtools' `flagstat_loop` exactly, with a QC-passed column and a QC-failed column (`0x200`) (P3c Task 3).</li><li>`-O` keeps its §6.1 meaning, output format; `-o x.json`/`x.tsv` infers it; the default is `text`. A `.gz`/`.bgz` suffix is stripped first and BGZF-compresses the output, as for `depth`, `samples` and `bedcov` `-o x.tsv.gz` (final fix wave M17).</li><li>The text, TSV and JSON layouts are samtools' byte for byte.</li><li>Percentages are computed as samtools computes them: `(n as f32 / total as f32) as f64 * 100.0`, printed `{:.2}`. With a total of 0 they print `N/A` (`null` in JSON).</li><li>Every record counts, unmapped and unplaced included.</li></ul>

<a id="d129"></a>**D129** **`check` reads alignments; `check --quick` is quickcheck.** <ul><li>**Full `check`** of a BAM, SAM or CRAM reads every record through `AlnSource`.<ul><li>Errors: records P3a rejects (P3a Task 2's list); a missing BGZF EOF marker; positions out of order when `@HD SO:coordinate` is declared (a decrease in `(ref id, pos)`, or a placed read after an unplaced one).</li><li>Warnings: a span past `LN`; identical records at one position (the P0 duplicate rule).</li><li>Under any other `SO`, order is reported but is not an error.</li><li>The summary adds mapped, unmapped-placed and unplaced counts, and the `SO`.</li></ul></li><li>**`--quick`** works on any format `check` reads. It checks:<ul><li>that the header parses;</li><li>for alignments, at least one `@SQ` unless `--unaligned` (samtools `-u`);</li><li>that the first record parses, or, for CRAM, the first container's header (so no reference is needed);</li><li>the BGZF EOF marker, or the CRAM EOF container, when the input is a regular file. stdin is not checked, as htslib.</li></ul></li><li>`--list-failed` prints only the failing paths, one per line, on stdout (samtools `-v`; gloci's `-v` is verbose logging). Without it, the usual summary is printed. `-q` silences warnings.</li><li>`--chrom-map` is a usage error (exit 2) for BAM, CRAM and SAM; `-g` and `--chrom-order` warn once and are ignored, as the header gives the references and the order.</li><li>The `--quick` read is bounded: header + first record + 28 bytes (BGZF), or header + first container + 38 bytes (CRAM).</li><li>CRAM 2.x is refused by name and version wherever the prelude is read: `#cram-limits`.</li><li>Any failing file → exit 1.</li><li>Pinned under `#quickcheck`: exit 1, not samtools' bit mask; VCF, BCF and BGZF BED pass (samtools: not sequence data); a corrupt first record fails (samtools never reads records).</li></ul>

<a id="d130"></a>**D130** **`gloci reheader HEADER IN [-o OUT]`.** <ul><li>HEADER is SAM header text, or a SAM/BAM/CRAM whose header is taken (as samtools); `-` reads stdin.</li><li>IN is a BAM or CRAM regular file. stdin is a usage error suggesting `gloci view - -o x.bam` first. `-o IN` replaces IN atomically.</li><li>**`@SQ` check.**<ul><li>The new list must keep the input's references in order with equal `LN`. Names may change, and new `@SQ` lines may follow the last old one, because records point at references by position.</li><li>For CRAM, an `M5` present in both lists must be equal.</li><li>Otherwise exit 1, naming both lines: `@SQ 3 of new.sam (SN:chr3 LN:1000) does not match @SQ 3 of x.bam (SN:chr3 LN:198295559); reheader keeps each read's reference by its position in the @SQ list, so change only SN: to rename, or use gloci view --chrom-map`.</li><li>samtools checks nothing: `#reheader-sq-check`.</li></ul></li><li>`@PG` follows D104 (`with_program`).</li><li>**BAM.**<ul><li>The input's EOF marker is checked first (`open_input`'s rule).</li><li>The new header is written as BGZF and flushed to a block edge.</li><li>Then `copy_from(input, out, extent)` runs, where extent is the old header's byte length in the decompressed stream.</li><li>One EOF marker ends the output.</li></ul></li><li>**CRAM.** The same file definition (version, file id), then a new header container: one raw `FILE_HEADER` block holding `i32 length + text`, with container and block CRC32 on 3.x. Then every byte from the old first data container to the end, verbatim. noodles' header writer is not used: it re-serialises the text and `expect`s a reference for every `@SQ` without `M5`.</li></ul>

<a id="d131"></a>**D131** **`gloci faidx REF REGION… [--regions-file BED] [-o OUT]`.** <ul><li>REF needs `.fai` (+ `.gzi`) (D108). Without one: exit 2 with `gloci index REF`. samtools builds it: `#fasta-implicit-index`.</li><li>With no regions: exit 2 naming `gloci index REF` (samtools then builds the index).</li><li>Regions use `Region::parse` (D8, htslib's rules). D8 gains htslib's `chr:-E` = `chr:1-E`. A region that does not parse is a usage error.</li><li>Each region prints `>` + the region text as typed + the strand suffix, then the bases wrapped at `--line-width N`. The default is the sequence's `.fai` line width; `0` means one line. A BED region prints as `chrom:start+1-end`; a zero-length BED region is skipped with one count warning.</li><li>An end past the sequence is cut there with a warning (samtools `Truncated sequence`). A start past it prints the header and no bases (samtools `Zero length sequence`).</li><li>An unknown sequence is a data error before any output. `--skip-invalid` skips the region entirely; samtools `-c` still prints its `>` line: `#faidx-missing-sequence`.</li><li>`--reverse-complement` (samtools `-i`) uses `fetch_rev` + `seq::complement`, the table samtools' `comp_base` uses.</li><li>`--mark-strand rc\|no\|sign\|custom,POS,NEG`: default `rc`, meaning `/rc` on reverse-complemented regions only. `sign` gives `(+)`/`(-)`.</li><li>`-o x.fa.gz` is BGZF, and `--write-index` writes `.fai`/`.gzi` (P3a Task 11's FASTA output path).</li></ul>

<a id="d132"></a>**D132** **`gloci dict REF [-o OUT]`** streams the FASTA (plain, gzip or BGZF; no index). <ul><li>It writes `@HD VN:1.0 SO:unsorted` unless `--no-header`.</li><li>Then, per sequence: `@SQ SN:<first word> LN:<n> M5:<md5>`, followed by `AH:*` (`--alt FILE`), `AN:` (`--alias`), `UR:`, `AS:` (`--assembly`) and `SP:` (`--species`), in samtools' order.</li><li>`LN` and `M5` cover only bytes `!`–`~`, with `a`–`z` uppercased. IUPAC codes, `*` and `-` count; spaces, tabs and `\r` do not.</li><li>`UR` defaults to `file://` + the canonical absolute path (none for stdin); `--uri` overrides it.</li><li>`--alias` follows samtools: strip or add `chr`; `M` adds `,chrMT,MT` and `MT` adds `,chrM,M`.</li><li>A duplicate name is a data error naming both lines. samtools writes both: `#dict-duplicate-names`.</li><li>Lengths are u64.</li></ul>

<a id="d133"></a>**D133** **`view --count` and alignment regions.** <ul><li>`--count` prints the number of records `view` would write (regions and D102 filters applied), as `N\n`, on stdout or `-o`. It works for every format `view` reads. It conflicts with `--header-only`, `-O` and `--write-index`.</li><li>`--regions-file BED` is samtools `-L`. Reads match a region under §4.3 on the D101 span (D116). A zero-length region matches reads under §4.3 (a point inside the span). It reads through the index when there is one; samtools `-L` scans.</li><li>Each record is written or counted once, however many regions it overlaps. samtools repeats it per positional region: `#view-overlapping-regions`.</li><li>Positional regions and `--regions-file` combine as a union (P0), and overlapping regions write each record once. samtools intersects them: `#view-regions-union`.</li></ul>

<a id="d134"></a>**D134** **`gloci head FILE [--headers N] [--records N]`** (samtools and bcftools `head`): all header lines and no records by default. <ul><li>Alignments print SAM text: the first N lines of the header text, then records through `open_alignment_writer` in its no-header SAM mode.</li><li>VCF/BCF prints VCF text with the header as stored, without the PASS line bcftools adds (`#head-vcf-pass-line`); BED, GFF and TSV print their header and data lines verbatim.</li><li>No `@PG` or `##glociCommand` line is added, because `head` shows the file as stored.</li><li>A BAM whose text has no `@SQ` for its binary references gets synthesised `@SQ SN LN` lines. samtools 1.21 prints nothing for it: `#head-notext-header`.</li><li>`-n`/`-h` are not copied (`--records`, `--headers`).</li></ul>

<a id="d135"></a>**D135** **`gloci samples FILE…`** reads only headers. <ul><li>Per file, one line per distinct `--tag` value (default `SM`) of its `@RG` lines, in first-seen order, or `.` when there are none.</li><li>Columns: `SAMPLE PATH`; then `Y`/`N` with `--show-index` (D107's index search); then, with `--match-reference FASTA` (repeatable), the first matching FASTA in samtools' order, or `.`. samtools checks the last-given FASTA first. A FASTA matches when its `.fai` has the same names and lengths in the same order as the `@SQ` lines.</li><li>`--column-names` prints `#<TAG> PATH [INDEX] [REFERENCE]`. `--tag` must be two characters.</li><li>samtools prints samples in hash order: `#samples-order`. A FASTA without `.fai` is a usage error (D108; samtools builds one): `#fasta-implicit-index`.</li></ul>

<a id="d136"></a>**D136** **`gloci flags [FLAGS…]`, and FLAGS parsing** (amends D102 for every FLAGS option). <ul><li>Each argument prints `0x<hex> TAB <dec> TAB <names>`. Names are comma-joined in bit order: `PAIRED PROPER_PAIR UNMAP MUNMAP REVERSE MREVERSE READ1 READ2 SECONDARY QCFAIL DUP SUPPLEMENTARY`; none gives an empty field.</li><li>With no arguments, it prints samtools' 12-line table (`%#6x %5d  %-15s%s`), without samtools' usage text.</li><li>FLAGS is a decimal number, a `0x` hex number, or comma-separated names, case-insensitive, up to `0xFFFF`.</li><li>A decimal with a leading zero (`010`) is a usage error, because samtools reads it as octal 8: `#flags-leading-zero`. `00`–`07`, the same in octal and decimal, are read (final fix wave M8).</li><li>Trailing text (`12abc`) is a usage error, where samtools reads 12.</li></ul>

<a id="d137"></a>**D137** **`gloci depth FILE…`: what counts.** <ul><li>**Records.** `AlnSource`, in file order. Records with no reference are skipped.</li><li>**Filters.** `--exclude-flags` defaults to `UNMAP,SECONDARY,QCFAIL,DUP`, samtools' set; `--exclude-flags 0` turns it off. The flag keeps its D102 meaning; only this command's default differs, and its help says so. Then `--require-flags` (all), `--min-mapq` (`-Q`), and `--min-read-length` (`-l`). The read length is `l_seq` minus its end soft clips, or, with SEQ `*`, the sum of `M I = X`.</li><li>**CIGAR walk** from `pos`:<ul><li>`M = X`: each base counts when `--min-baseq` (`-q`) is 0 or its quality is at least that. A missing quality (`0xFF`) passes. With SEQ `*`, every base passes; samtools reads past the record there.</li><li>`D`: counts only with `--count-deletions` (`-J`), each base gated by the quality of the *next* query base, as samtools does.</li><li>`N`: never counts.</li><li>`I S`: advance the query. `H P`: nothing.</li></ul></li><li>**The span** is the D101 span (`bam_endpos`; a placed unmapped read, kept only when `UNMAP` is not excluded, spans `[pos, pos+1)`), cut at `LN` with one warning. samtools prints rows past `LN`: `#depth-past-reference-end`.</li><li>**Order.** Any decrease in `(ref id, pos)` within an input is exit 1 with the `gloci sort` hint (D103). samtools notices only a read that ends before its last printed row: `#depth-order-check`.</li></ul>

<a id="d138"></a>**D138** **`depth`: which rows.** <ul><li>Each row is `chrom TAB pos(1-based) TAB depth…`, one depth column per input in argument order, in `@SQ` order and then position order.</li><li>A position is printed when it lies in a passing read's span in any input. Zero-depth positions inside spans (deletions, introns, filtered bases) print 0, as samtools.</li><li>`--all-positions` (`-a`) adds every position of each reference that has a passing read. `--all-references` (`-aa`) adds every position of every reference.</li><li>`--region` (repeatable, samtools `-r`) and `--regions-file` (`-b`) limit rows to their union, each position once. Reads come through the index when there is one; otherwise the input is scanned with a warning, where samtools `-r` stops with an error.</li><li>With regions, `--all-positions` prints every position in the regions. That equals samtools `-a -r` and `-aa -b`. samtools `-a -b` skips regions on references with no passing read: `#depth-regions`.</li><li>`--column-names`: `#CHROM POS <path>…` (paths as given).</li><li>One merged stream at every `-t`; threads go to BGZF/CRAM decoding, so rows and stderr never depend on `-t` (final fix wave I3: per-reference `run_chunks` jobs spilled rows to LZ4 and drained them on one thread, slower than the stream).</li></ul>

<a id="d139"></a>**D139** **`depth --skip-mate-overlap`** (samtools `-s`), per input. <ul><li>It applies to a read with `PAIRED` set and `MUNMAP` clear.</li><li>If the read's name is pending, the read takes that entry's end as its clip, and the entry is removed. Bases (and counted deletions) before the clip are not counted.</li><li>Otherwise the read stores `name → end` when its mate is on the same reference with `pos ≤ mpos ≤ end`.</li><li>An entry is dropped once a read starts after its `mpos`, and at each reference change. So the table holds only reads whose mates are still ahead, which is ∝ depth.</li><li>samtools also stores reads whose `mpos` is −1 or behind them, and never drops entries. A later alignment with the same name, anywhere in the file, is then clipped by a stale end, even on another reference. Its memory grows with the number of pairs. Results differ only for such templates (a supplementary alignment after its resolved pair, an unknown mate position): `#depth-mate-overlap`.</li></ul>

<a id="d140"></a>**D140** **`gloci bedcov BED FILE…`** <ul><li>Each FILE needs a `.bai`/`.csi`/`.crai`. Without one: exit 2 with `gloci index FILE`, as samtools exits 2.</li><li>BED lines may come in any order, as in `getfasta`: each region is a random-access query and the output follows the BED. Each worker keeps one reader per FILE and seeks it per region (a CRAM opens per region) (final fix wave M16). Comment, `track`, `browser` and blank lines are skipped and not echoed.</li><li>Each data line is echoed verbatim. Then come one column per FILE for each of the sum, the `--bases-at-depth N` count (`-d`), and the `--read-count` (`-c`), in that order, as samtools.</li><li>**Sum.** The total, over `[start, end)`, of the per-base depth of passing reads. It uses depth's core with `M = X` always, `D` unless `--split-deletions`, and `N` unless `--split`; these are the D105 flags with their meaning, so samtools `-j` = `--split --split-deletions`.</li><li>**Bases at depth.** Uses the same depth. samtools drops `D` and `N` from both columns whenever `-d` is given: `#bedcov-depth-threshold`.</li><li>**Read count.** Passing reads whose D101 span overlaps the region under §4.3. A zero-length region has no bases and counts no reads, as samtools 1.21 does.</li><li>**Filters.** `--exclude-flags` defaults to samtools' `UNMAP,SECONDARY,QCFAIL,DUP`; `--min-mapq` applies. Unmapped reads never count, as htslib's pileup skips them.</li><li>**Errors.** A BED chromosome not in the `@SQ` list is exit 1 naming the line, or skipped and counted with `--skip-invalid`. samtools prints an error, goes on, and exits 2: `#bedcov-bad-line`.</li><li>`--column-names`: `#chrom start end <path>_cov… <path>_depth… <path>_count…`.</li><li>Batches of 256 lines run on ≤ threads workers, each with its own indexed readers. Output stays in BED order.</li><li>Use it where bedtools `multicov` was used (§2 non-goal).</li></ul>

<a id="d168"></a>**D168** **`gloci tag ALN -b FILE…`** (bedtools tag). <ul><li>**Records.** Every record of ALN (BAM, CRAM, SAM, or `-` for standard input), read through `AlnSource` in input order and written unchanged but for the tag: BAM bytes get the aux field appended, a SAM line `\tXX:Z:value`. Output in the input's format (SAM for SAM, BAM for BAM and CRAM, which is never written); `-o`'s extension and `-O` choose BAM or SAM; `--write-index` and `--compression-level` as for `view`.</li><li>**Which reads.** A read is tagged only when FLAGS bit 0x4 is clear (secondary and supplementary alignments included), as bedtools tests `IsMapped`. Its span is POS plus the lengths of its `M D N = X` operations (BamTools' `GetEndPosition`): introns and deletions count, clips and `P` do not, and a read with none spans nothing and is never tagged (bedtools divides by its length of 0).</li><li>**Features.** Every `-b` file (BED, bedGraph as BED, GFF, GTF) is read into one `IntervalIndex`, the index of `--unsorted` and the `pair-*` commands (D61, D154). A zero-length BED record is `[start-1, end+1)` (a record at 0 is `[-1, 1)`), as bedtools' BED parser widens it; GFF is `[col4-1, col5)` and never widened. VCF and the other formats are exit 2 naming `gloci convert` (`#tag-feature-formats`). Memory grows with the features alone, whatever the size of ALN: about 140 bytes per feature while the index is built, plus the text the tag takes from it (none for labels; its name or score; its whole interval), measured at 3.6 times a BED6 file for `--labels`, 4.7 times for `--intervals`, and checked by the nightly `tag_holds_the_features_and_streams_the_reads` (4 and 5 times the file, plus the streaming ceiling).</li><li>**Hits.** A feature hits when `shared / span >= --fraction`, both sides 32-bit floats as bedtools computes them (`shared` is `min(ends) - max(starts)`), so touching features never hit; `--fraction` takes what the other commands take (`0.5`, `50%`, above 0 and at most 1; default bedtools' 1e-9, any shared base) and applies in every mode. `-s` (`--same-strand`) wants the feature's strand to be the read's, `-S` (`--opposite-strand`) the other one. The names and the rule are `intersect`'s (spec section 4.3): a feature of unknown strand (`.`, no strand column, any text but `+` or `-`) matches neither, and each `-b` file with such features gets one warning. bedtools tag compares the strand text, so under `-S` such a feature tags reads on both strands (`#tag-unknown-strand`); gloci does not follow it, because one flag means one thing across gloci and a strand nobody gave is not the opposite one (owner's ruling on review, 2026-11-15).</li><li>**Value.** Per `-b` file with a hit, in `-b` order, a part: its `--labels` entry (the default mode), or the `--names` (BED column 4, GFF column 3), `--scores` (column 5 or 6, as written) or `--intervals` (`label:chrom:start-end,name,score,strand`, columns a line lacks empty) of each hit joined by `,`; parts are joined by `;`. A file's hits come in bedtools' bin order (7 levels from 16 kb bins up, each 8 times larger; finer level first, then bin, then file order), duplicates kept. An empty part counts, so a value may be empty or end in `;`. The tag (`--tag`, default `YB`, a letter and a letter or digit) is type `Z`, added after the other tags even when one of that name is there: bedtools adds a second one.</li><li>**Options.** `--labels L,…` gives one label per `-b` and is required by the default mode and `--intervals`, refused with `--names` and `--scores`; `--names`, `--scores` and `--intervals` exclude each other. bedtools' looser handling of these is `#tag-option-values`.</li><li>**Checking.** bedtools writes BAM through BamTools, so as D165 says the cases compare gloci's SAM output (and, live, its BAM output read back the same way) with bedtools' BAM read back by `samtools view -h`, `@PG` lines left out; two more compare gloci's BAM with bedtools' decompressed (compare mode `bam`): the records are byte for byte BamTools', `bin` included. Fixtures in `xtask/diff/inputs/tag/`, BAM and CRAM rebuilt by `make-tag.sh`.</li></ul> **[owner, 2026-11-15]**

<a id="d169"></a>**D169** **`gloci igv BED`.** Writes bedtools' IGV batch script: `snapshotDirectory PATH`, `load SESSION`, then per record `goto chrom:start-end`, `sort KEY`, `collapse`, `snapshot chrom_start_end[_name][_slopN].ext`. Options: `--path` (`-path`, default `./`, written as given), `--session` (`-sess`), `--sort` (`-sort`: base, position, strand, quality, sample, readGroup), `--collapse` (`-clps`), `--name` (`-name`), `--slop N` (`-slop`), `--image png|eps|svg` (`-img`). Bug-compatible on purpose: the goto line shows the 0-based start (`chr1:100-200` for BED `100 200`), a slop larger than the start gives a negative start, a zero-length BED record is shown as `[start-1, end+1)` (`-1` at 0) and named that way, GFF uses `start-1` and no widening, a VCF record is `[POS-1, POS-1+len(REF))` whatever its ALT or END, named `REF/ALT` with `_ID` when the ID is not `.`, `--name` names a GFF record by its feature type, a record with an empty name is an error under `--name`. Every BED and GFF record must have the first record's column count (error naming the line; VCF is not checked), one trailing tab on a line is ignored, input order is kept, no sorting. Reads BED, bedGraph, GFF/GTF and VCF. Differences: `--image`, `--slop` and `--sort` values are checked (`#igv-option-values`); nothing is written when the input is not recognised (`#browser-unrecognised-input`). **[owner, 2026-11-15]**

<a id="d170"></a>**D170** **`gloci links BED`.** Writes bedtools' HTML page: a fixed head whose title is the input's name (`stdin` for `-`) and whose heading says `BED Entries from: stdin`, one table row per record with a link `BASE/cgi-bin/hgTracks?org=ORG&db=DB&position=chrom:start-end` whose text is `chrom:start+1-end`, and the closing tags. Options `--base` (default `http://genome.ucsc.edu`), `--org` (`human`), `--db` (`hg18`). The cells after the link follow bedtools' record types: BED of 4, 5 or 6, 9 or 12 columns gets name, then score, then strand as far as it has them, BED of any other column count gets none; GFF gets feature type, score and strand; VCF of 9 or 12 columns gets `REF/ALT_ID`, an empty score and `+`, other VCF none. Nothing is HTML-escaped. Positions, widening, column count check and trailing tab are those of D169. **[owner, 2026-11-15]**
