# gloci `vcf query` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `gloci vcf query FILE -f FORMAT [-H] [selection options] [-o OUT]`: bcftools 1.21 `query -f`'s format language (the common subset), on the shared `vcf` selection stage, with bcftools query's sample-level filter rule, byte-identical to bcftools 1.21 except where `docs/differences.md` says otherwise.

**Architecture:**
- `gloci-vcf/src/query/` holds the format language: `QueryFormat::parse` (syntax, no header), `QueryFormat::resolve` (names against the header, giving a `Query`), and `Query::write_record` / `Query::write_header`, which render one VCF text line and the `-H` line.
- `gloci-vcf/src/expr/` gains `Expr::eval_query`, bcftools query's per-sample evaluation: a record verdict plus a per-sample pass mask. `Expr::eval` (D71's site rule) is untouched.
- `gloci-ops/src/vcf_select.rs` carries the mask through the D157 workers (`Hit::sample_pass`), only when a consumer calls `SelectStage::filter_samples()`. `gloci-ops/src/vcf_query.rs` drives the stage like `extract_table` does: each passing record is turned into VCF text by the stage's `Lines` (sample selection and masks applied; BCF rendered as bcftools does), then rendered by the `Query`.
- The CLI is a new `VcfCommand::Query`, run like `vcf extract`; Python gets the step `vcf_query` (D87).

**Tech Stack:** Rust workspace crates only; no new dependency. `itoa` and `regex` are already gloci-vcf dependencies; float printing reuses gloci-io's htslib `kputd` (made public). Reference tool: bcftools 1.21 in `gloci-diff:p0` (already in the image; the Dockerfile does not change).

**Spec:** `docs/superpowers/specs/2026-11-17-tracks-query-coverage-liftover-design.md`, section "Feature 2: `gloci vcf query`", plus its "Owner constraints", "Common to all four" and "Order of the work" sections.

**Builds on:** D157 (parallel selection: `SelectStage`, `run_selection`, `Hit`), D71 (filter expressions), D50 (masking), D73 (`vcf extract`, whose `Lines` and output handling this reuses), D17 (output format from `-o`), D87 (Python placement).

**Out of scope:** bcftools query's `-HH`, `-l`, `-u`, `-a`, `-N`, `--force-samples`; functions (`%IUPACGT`, `%PBINOM(...)`, `%MASK`, `%GT_TO_PROB3`...); the per-sample expression operators `&` and `|` (still a usage error, as in every `vcf` command); sample order as given to `--samples`.

**Done when:** every construct in D172 has a golden case against bcftools 1.21 or a documented difference with an `expected_difference` case; the output is the same at `-t 1/2/8` on VCF and BCF; D172, the migration row, the design paragraph, the changelog entry, SKILL.md and the Python stub are in.

**Format strings in this plan:** written as bcftools takes them. In Rust tests, pass them as raw strings (`r"%POS\t%REF\n"`: gloci's parser sees backslash-t), and write expected output with real tabs and newlines (`"10\tA\n"`).

```
<a id="d172"></a>**D172** **`gloci vcf query FILE -f FORMAT`** (bcftools 1.21 `query`; owner request 2026-11-17). <ul>
<li>**Selection.** Every `vcf` selection option, through the shared stage (D157); `-t` adds selection workers and never changes the output. `--vcf-span` defaults to `ref`, as for `vcf stats`, so a symbolic ALT without END is read, as bcftools reads it.</li>
<li>**Fields.** `%CHROM %POS %POS0 %END %END0 %ID %REF %ALT %ALT{N} %FIRST_ALT %QUAL %FILTER %TYPE`, `%INFO` (the column), `%INFO/TAG` and `%TAG` (an INFO tag), `%TAG{N}` (its value N, from 0), `%LINE` (the record, without a newline). Inside `[ ]`, once per printed sample: `%SAMPLE`, `%GT`, `%TGT` (GT with allele bases), FORMAT tags and their `{N}`; a bare `%TAG` there is the FORMAT tag when the header declares one, else the INFO tag; site fields may appear there and repeat per sample. `\t`, `\n` and `\\` are escapes; everything else is literal text. A FORMAT that holds no newline gets one at its end, as bcftools 1.21 does.</li>
<li>**Values.** Missing is `.`, also for a subscript past the end (bcftools prints a one-value INFO number for any subscript: `#vcf-query-index-past-end`). Vectors are comma-joined; an INFO flag is `1` when set and `.` when not, whatever its subscript. `%QUAL` and Integer and Float tags print as bcftools prints them: an integer re-read (`007` is `7`), a float read as a 32-bit float and written as htslib writes it (`0.600000` is `0.6`, `1e-5` is `1e-05`); a value that does not read as its declared type is exit 1 naming the record and the tag. Other values print as written. `%END` is INFO/END when it is at least POS, else POS + len(REF) − 1. `%TYPE` lists htslib's variant classes of the ALTs in the order `SNP,MNP,INDEL,OTHER,BND,OVERLAP`, or `REF` when there are none (also for an ALT of `.`). For VCF input, `%INFO` and `%LINE` are the record's text as written, with the sample selection and masks applied as `vcf filter` writes them; for BCF input they are as bcftools prints them (`#vcf-query-values`).</li>
<li>**Usage errors** (exit 2, naming the construct and its column): `%` without a field name (so `%%`), any other escape (`\x`), `[` inside `[ ]`, `]` without `[`, an unclosed `[`, a `{` after a field that does not make `{N}`, a subscript on a field that takes none, `%SAMPLE`, `%GT`, `%TGT` or a FORMAT tag outside `[ ]`, `%LINE` inside it, `%FMT/TAG` and `%FORMAT/TAG` (write `[%TAG]`), a name that is neither a field above nor a tag the header declares, and `-H` with `%LINE`. bcftools reads several of these loosely: `#vcf-query-format-strict`. The expression grammar is D71's, so bcftools' per-sample `&` and `|` stay usage errors.</li>
<li>**`-H`** writes bcftools' header line first, also when no record follows: `#`, then each field as `[N]NAME` (N counts from 1 along the line; NAME is the field's keyword, a tag's name without `INFO/` or subscript, `GT` for `%TGT`, and `INFO` for `%INFO`, where bcftools writes `(null)`: `#vcf-query-header-info`), literal text as it is. A `[ ]` block repeats per printed sample, each NAME preceded by `SAMPLE:`. A block that holds a newline, and every block after it, is written once with its newlines left out, and the line then gets one more newline. There are no `SAMPLE:` prefixes when any block holds a newline, or when `--include`/`--exclude` reads genotypes (GT, FORMAT fields, `N_PASS`, computed `MAF`, `AC`, `AN`, `F_MISSING`, `N_MISSING`).</li>
<li>**Sample-level filters** (bcftools query's rule, measured on bcftools 1.21; every other command keeps D71's site rule). Each node of the expression gives either a site value or a pass per selected sample: a comparison of `GT`, `FMT/DP` or `FMT/GQ` gives per-sample passes (with a subscript, only that sample can pass, and only when it is selected); anything else, `N_PASS` and the computed fields included, gives a site value. `A && B`: two site values AND; a site value with per-sample passes keeps them when it holds and fails otherwise; two per-sample results pass when both pass, and a sample passes when it passes either. `A || B`: two site values OR; a site value that holds makes every selected sample pass, otherwise the per-sample side stands; two per-sample results pass when either passes, and then every selected sample passes. `!`, a gloci extension, flips a site value, and flips each selected sample's pass (the result passes when a sample then passes). With `--include`, a record prints when the result passes, and inside `[ ]` only its passing samples print when the result is per sample. With `--exclude`, a site value that holds drops the record; per-sample passes are flipped and the record prints with the samples that now pass, or is dropped when none does; a result that fails prints the record with every sample. Masked genotypes (D50) read as missing. The passes travel with each batch through the D157 workers as `Hit::sample_pass`; only `vcf query` asks for them.</li>
<li>**Samples** print inside `[ ]`, and are named by `-H`, in the order `--samples` or `--samples-file` gives them, as bcftools query prints them (`--samples s3,s1` prints s3 first): a script that prints `[\t%GT]` without `%SAMPLE` must get the columns it asked for. Without those options, and with `--exclude-samples`, in the header's order. An expression's sample subscripts keep gloci's rule (they number the whole header), where bcftools numbers the selected samples (`#vcf-query-samples`).</li>
<li>**Output.** Text, to stdout or `-o FILE` (atomic; a name ending in `.gz` or `.bgz` is BGZF; a `.bam`, `.bcf` or `.cram` name is exit 2).</li>
<li>**Python** (D87): the step `vcf_query`; output `Table`, and with `print_header` its first line is the header (`HeaderLine`).</li></ul>
```

```rust
#[derive(Clone, Debug)]
pub struct QueryFormat { /* the source text and its syntax items */ }
impl QueryFormat {
    /// Syntax only, no header: errors are usage errors that quote the format and give a 1-based column.
    pub fn parse(src: &str) -> Result<QueryFormat, UsageError>;
    /// Bind names to fields and declared tags; `print_header` is `-H` (refused with %LINE).
    pub fn resolve(&self, header: &VcfHeader, print_header: bool) -> Result<Query, UsageError>;
}
#[derive(Clone, Debug, PartialEq)]
pub struct Query { pub pieces: Vec<Piece> }
#[derive(Clone, Debug, PartialEq)]
pub enum Piece { Text(Vec<u8>), Field(Field), Block(Vec<Piece>) }
#[derive(Clone, Debug, PartialEq)]
pub enum Field {
    Chrom, Pos, Pos0, End, End0, Id, Ref, Alt(Option<usize>), FirstAlt, Qual, Filter, Type,
    Info, InfoTag(Tag), Line, Sample, Gt, Tgt, FormatTag(Tag),
}
#[derive(Clone, Debug, PartialEq)]
pub struct Tag { pub name: Vec<u8>, pub ty: TagType, pub sub: Option<usize> }
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum TagType { Integer, Float, String, Flag } // Character and a missing Type are String
```

Syntax rules (parse): after `%`, a name of `[A-Za-z0-9_.]+`; when that name is `INFO`, `FMT` or `FORMAT` and `/` follows, the `/` and a second name are part of it; then an optional `{digits}`. Adjacent literal text and escapes merge into one `Text`. Resolution rules are D172's. After resolving, when no `Text` anywhere holds `\n`, a `Piece::Text(b"\n")` is appended at the top level. Every error message starts `invalid query format "<src>": ` and ends ` (column N)`.

```rust
/// The sample columns of a line given to [`Query::write_record`].
pub struct SampleCols<'a> {
    /// Header index of each sample column of the line, in column order (ascending).
    pub kept: &'a [usize],
    /// Positions in `kept`, in the order the samples print inside `[ ]` and in the -H line:
    /// the order `--samples`/`--samples-file` gave, else `0..kept.len()`.
    pub order: &'a [usize],
    /// Every sample name of the header.
    pub names: &'a [Vec<u8>],
    /// Which header samples print inside `[ ]`, by header index; `None`: every kept sample.
    pub pass: Option<&'a [bool]>,
}
impl Query {
    /// Append the output of one VCF text line (no newline; at least 8 columns).
    /// Err names the tag and, for a FORMAT value, the sample: `INFO/I value "abc" is not an Integer`.
    pub fn write_record(&self, line: &[u8], samples: &SampleCols<'_>, out: &mut Vec<u8>) -> Result<(), String>;
    /// Append the -H line for printed samples `names`; `filter_reads_samples` drops the `SAMPLE:` prefixes (D172).
    pub fn write_header(&self, names: &[&[u8]], filter_reads_samples: bool, out: &mut Vec<u8>);
}
```
