# `gloci liftover` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `gloci liftover FILE --chain CHAIN` moves BED, bedGraph and GFF/GTF records to another assembly by CrossMap 0.7.4's rules, checked record for record against CrossMap in the comparison image.

**Architecture:**
- `gloci-io/src/chain.rs` parses a chain file (plain, gzip, BGZF) itself, reading what CrossMap reads (any whitespace, 12- or 13-field headers, repeated ids), into aligned blocks indexed per source chromosome with `rust-lapper`. (chainfile was the design's pick; it rejects both published test chains and holds about 180 bytes a block, so the controller dropped it on 2026-11-17: see note 1.)
- `gloci-ops/src/liftover/` applies CrossMap's rules per format on top of those pieces: chromosome-name lookup and style, BED interval path, BED12 blocks, GFF, and region-style merging.
- `gloci/src/commands/liftover.rs` wires the reader, the mapped and unmapped writers, and the warnings.

**Tech Stack:** Rust 1.100.0 (MSRV 1.91); `rust-lapper` 2.0 (new, MIT); the existing gloci readers and writers. Reference tool: CrossMap 0.7.4 (PyPI wheel, GPL-3.0, test-only), added to `gloci-diff:p0` in Task 2.

**Spec:** `docs/superpowers/specs/2026-11-17-tracks-query-coverage-liftover-design.md`: "Feature 4: `gloci liftover`" (as amended in d1c0b70c and cb1896cb), the Liftover row of "Approaches considered", "Owner constraints", "Common to all four" and "Order of the work".

**Builds on:** the depth-summaries lane (D173), already merged in this worktree line. This plan touches none of its files.

**Findings that shaped this plan** (each checked on 2026-11-17):
1. **`chainfile` 0.5.0 reads neither published chain this plan tests with,** when the text is given to it as is (checked with a scratch crate):
   - Ensembl's `GRCh37_to_GRCh38.chain.gz` separates block numbers with spaces. chainfile wants tabs: `invalid alignment data record ... line: 167417 50000 80249`.
   - With tabs, chainfile still fails: every Ensembl chain appears twice, under `1` and under `chr1`, with the same id (885 ids repeat). The error is `duplicate chain id 2 with inconsistent headers`.
   - The T2T consortium's `grch38-chm13v2.chain` separates header fields with tabs. chainfile wants single spaces: `expected 13 fields, found 1`.

   Normalised, both chains build and chainfile's pieces equal CrossMap's, but rewriting every chain's text to suit a library is a workaround, not a reader. So gloci parses chains itself (the format is a header line and three-number block lines) and indexes the blocks with `rust-lapper`, which chainfile uses too. Task 3's tests pin that the pieces equal CrossMap's.
2. **Every bioconda `crossmap` build (0.6.5 to 0.7.4) depends on `ucsc-wigtobigwig`,** which the owner constraints forbid. So the image takes CrossMap 0.7.4 from PyPI with `--no-deps`, and its dependencies come from conda-forge and bioconda (Task 2). Note that `CrossMap --version` prints `0.7.3` for 0.7.4, because the version string was not bumped.
3. **The CrossMap rules below were read from its behaviour, not its code.** Each rule was checked by running CrossMap on the fixtures of Task 2, and every expected line in this plan is CrossMap's actual output on those fixtures. CrossMap's `bed`, `gff` and `region` modes give the BED, GFF and `--merge-segments` rules. Its `wig` mode, which drops records silently, is the reference only for the documented bedGraph difference.
4. **Memory of the chain index.** chainfile held about 180 bytes per aligned block (peak RSS 20 MB for Ensembl GRCh37→GRCh38, 84,109 blocks; 132 MB for T2T GRCh38→CHM13v2, 707k blocks). gloci's own index keeps one `rust_lapper::Interval<u64, Block>` per block, with `Block { target_start: u64, chain: u32 }`: about 40 bytes, so about 4 MB and 30 MB. That cost is fixed per chain; records stream.

## Decision D174: the rules

`docs/decisions.md` gets `<a id="d174"></a>**D174** **\`gloci liftover\`: CrossMap's rules** (owner, 2026-11-17)`. It holds one bullet per rule below, each added by the task that implements it.

| # | Rule | Task |
|---|---|---|
| R1 | **Chain files.** `--chain` takes a path or `-`, plain, gzip or BGZF (told by magic bytes). gloci's parser reads what CrossMap reads: any whitespace, headers of 12 or 13 fields (the id is ignored), `#` comment lines, CRLF, chains without blank lines between them. It writes canonical text (header `chain 0 tName tSize + tStart tEnd qName qSize qStrand qStart qEnd N`, block lines `size\tdt\tdq`, a last `size` line, and a blank line). Each chain is renumbered `N` = its 1-based place in the file, because Ensembl repeats ids for its `chr` copies and T2T uses id 0 twice. The text then goes to `chainfile::liftover::machine::Builder`. Errors, each exit 1 naming `CHAIN line N`: a source (tStrand) other than `+` (CrossMap stops on this too); a target strand other than `+`/`-`; non-numeric or out-of-range numbers (start ≤ end ≤ size on both sides); a block line before any header, of 2 or 4+ numbers, or a header before the previous chain's final 1-number line; blocks that do not reach exactly tEnd and qEnd; one chromosome name with two sizes (on either side; names both lines); a file with no chain; a file that ends inside a chain. CrossMap reads all of these but the first without a word: `#liftover-chain-checks`. A chainfile error that still slips through is exit 1 naming the chain file. Memory: about 180 bytes per block (Finding 4). | 1 |
| R2 | **Pieces.** A record's pieces are the aligned blocks that overlap it, clipped to it. A block overlaps `[s,e)` when `block.start < e && block.end > s`, so a zero-length record `[p,p)` is found only strictly inside a block. Pieces are ordered by source start, then by the chain's place in the file, which is CrossMap's order: its interval tree returns equal starts in file order. Target coordinates are always forward-strand. A piece of a `-` chain has `reverse = true`. | 1 |
| R3 | **Inputs and outputs.** Input is BED (any column count from 3) or bedGraph, plus GFF3 and GTF (Task 6). VCF/BCF is exit 2: "VCF liftover is not supported yet (CrossMap vcf)". WIG is exit 2, suggesting `gloci convert x.wig -o x.bedgraph`. BEDPE is exit 2. Alignments are refused by the D100 gate. The output is the input's format family, written in input order, with header lines only under `--header` (CrossMap writes none). The help says to pipe the output through `gloci sort`. | 4 |
| R4 | **Chromosome names.** A record's chromosome is looked up in the chain as written, then with every `chr` removed, then with `chr` prepended (CrossMap). `--chrom-style` names the target chromosome. The default `as-input` is CrossMap `--chromid a`: if the input name starts with `chr`, the target gets `chr` prepended unless it starts with `chr`; otherwise every `chr` is removed from a target that starts with `chr`. `short` (`s`) removes every `chr` from a target that starts with `chr`. `long` (`l`) prepends `chr` unless present. `chain` (`n`) keeps the chain's name. `--chrom-map` renames input chromosomes before the lookup. `chrM` with an Ensembl chain finds no `M` and is unmapped, never sent to `MT`. | 3 |
| R5 | **BED interval path,** for records with fewer than 12 columns, or any record under `--ignore-blocks`. One output record is written per piece, in piece order. Columns 1–3 become the styled target name and the piece's target start and end. Column 6, when it is exactly `+` or `-`, becomes `+` if `piece.reverse == (column 6 is "-")`, else `-`; every other column is written byte for byte. A record with no piece is unmapped. Columns split on tabs only (CrossMap splits on any whitespace: `#liftover-bed-fields`). The strand comes from column 6 only (CrossMap takes the rightmost field equal to `+` or `-` and rewrites every such field: `#liftover-strand-column`). bedGraph follows the same path (CrossMap's `wig` mode, which drops split records and sums overlaps: `#liftover-bedgraph`). | 3 |
| R6 | **Unmapped records and warnings.** An unmapped record is written exactly as read, with no reason column, to `--unmapped FILE`. That file is the input's format family; `.gz` makes it BGZF; `-` is stdout when `-o` names a file. CrossMap appends `Unmap` and writes `OUT.unmap` unasked: `#liftover-unmapped-file`. Without `--unmapped`, one warning counts the unmapped records, by reason. One warning counts records split into several records and records that lost bases no piece covers (CrossMap does both silently). An invalid line is exit 1 naming the line, or skipped and counted under `--skip-invalid`; CrossMap writes it to the unmapped file with a reason and goes on: `#liftover-invalid-lines`. | 3, 4 |
| R7 | **Threads and memory.** Records are mapped on one thread, in input order. `-t` speeds BGZF reading and writing only, and the output is identical at every `-t`. Memory is the chain index plus one batch. | 4 |
| R8 | **BED12 block path,** for records with 12 or more columns unless `--ignore-blocks` is given (Task 5 has the details). Each block needs exactly one piece. All pieces must share the styled target chromosome and mapped strand. Blocks are rebuilt in input order, and thick ends follow their blocks (`#liftover-bed12-thick`). The result must pass CrossMap's BED12 check, plus gloci's own: blocks ascending and not overlapping (`#liftover-bed12-block-order`). A strand other than `+`/`-` maps as `+` and is kept, where CrossMap stops with an exception (`#liftover-bed12-unknown-strand`). Columns 13 and up are kept, where CrossMap drops a 13–19 or 21+ column record without a trace and cuts a 20-column one to 12 (`#liftover-bed-fields`). | 5 |
| R9 | **GFF/GTF** (Task 6 has the details). Column 7 must be `+`, `-` or `.`, else unmapped. The feature `[start-1, end)` needs exactly one piece: none or several leaves it unmapped. With one piece, it is written with columns 1, 4, 5 and 7 replaced. A piece shorter than the feature is written shortened and also to the unmapped output, as CrossMap does. A `.` strand stays `.`, where CrossMap writes `+` or `-` (`#liftover-gff-unknown-strand`). | 6 |
| R10 | **`--merge-segments [--min-ratio F]`** is CrossMap `region [-r F]`; the default F is 0.85. With 0 pieces the record is unmapped. With 1 piece it follows R5. With 2 or more, `ratio = Σ piece source lengths / record length` in f64 (1.0 for a zero-length record). The checks run in order: `ratio < F`, then different target chromosomes, then different mapped strands; each leaves the record unmapped. Otherwise one record `[min start, max end)` is written, with column 6 set to the common mapped strand. Differences, under `#liftover-merge-segments`: no `map_ratio=` column; the strand is set (CrossMap keeps the input's); mixed strands are unmapped (CrossMap merges them); a zero-length record does not stop the run (CrossMap raises ZeroDivisionError); a BED record of 12 or more columns without `--ignore-blocks` is exit 2 (CrossMap moves only columns 1–3 and leaves the blocks wrong). GFF input is exit 2. | 7 |
| R11 | **Python.** `liftover` is a step (D87). | 4 |
| R12 | **Reference.** The reference is CrossMap 0.7.4 from PyPI (Finding 2). Fixtures are hand-built under `xtask/diff/inputs/liftover/`. Real data is a slice of Ensembl's GRCh37→GRCh38 chain. | 2, 8 |
| R13 | **Built-in chains,** pending the owner's decision. | 9 |

## Review Focus

1. **Chain files as published.** These must all load and give CrossMap's pieces, where chainfile alone rejects them: Ensembl's space-separated block lines and repeated ids, T2T's tab-separated headers and id 0 used twice, 12-field headers, CRLF, `#` comments, missing blank lines, gzip and BGZF. Pinned by Task 1 `published_layouts_load` and `compressed_chains_load_the_same`.
2. **Input names against chain names.** `chr1` against `1`, `chrM` against `MT` (unmapped, never MT), names that hold `chr` inside, and `--chrom-map` before the lookup must follow R4 exactly. Pinned by Task 3 `chrom_names_follow_crossmap` and `chrm_is_not_mt`.
3. **Records at block and chain edges.** A point at a block start, at a chain start or at a chain end; a record ending exactly at a block end; a record starting at tEnd. Pinned by Task 3 `bed_lifts_as_crossmap` (toy records r10, r18, r20, r25, r26).
4. **Two outputs.** Both outputs on stdout, the same path for both, a failure halfway (neither file may be left behind), `-t` invariance, header lines. Pinned by Task 4 `both_outputs_on_stdout_is_a_usage_error`, `same_path_for_both_outputs_is_a_usage_error`, `failed_run_leaves_no_outputs`, `output_is_the_same_at_every_thread_count`, `header_lines_only_with_header`.
5. **Large inputs.** Memory must not grow with the record count. Pinned by Task 8 `liftover_memory_is_flat`.

**Interfaces:**
- Produces:
  ```rust
  pub struct ChainIndex { /* per source chromosome: rust_lapper::Lapper<u64, Block>; Vec<ChainInfo>; block count */ }
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub struct ChainInfo { pub line: u64, pub source: String, pub target: String, pub target_size: u64, pub reverse: bool }
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub struct Segment { pub chain: u32, pub source: Interval, pub target: Interval, pub reverse: bool }
  #[derive(Debug, Clone)]
  pub struct SourceRef(usize); // index of the source chromosome's lapper
  impl ChainIndex {
      pub fn load(path: &str) -> Result<ChainIndex, IoError>;            // `-` = stdin (claims it)
      pub fn parse(name: &str, text: &[u8]) -> Result<ChainIndex, IoError>;
      pub fn source(&self, chrom: &str) -> Option<SourceRef>;            // exact source name only
      pub fn segments(&self, src: &SourceRef, iv: Interval, out: &mut Vec<Segment>); // clears `out`; R2 order
      pub fn chain(&self, i: u32) -> &ChainInfo;                         // i = Segment::chain, 0-based file order
      pub fn chains(&self) -> usize;
      pub fn blocks(&self) -> usize;
  }
  ```
  `Interval` is `gloci_core::Interval`. `Segment::target` is in forward coordinates: for a piece of a reverse chain (qStrand `-`), whose query coordinates count from the end of the target chromosome, the forward interval is `[qSize - qEnd_piece, qSize - qStart_piece)`. Errors are `IoError::Parse { path, loc: Loc::Line(n), msg }`. Decompression follows `genome.rs`: `open_raw` plus `flate2::read::MultiGzDecoder` when the first bytes are `1f 8b` (BGZF is gzip).

**Files:**

**Interfaces:**
- Consumes: `gloci_io::bed12_blocks(line) -> Result<Option<Vec<Interval>>, String>`, `ChainIndex::segments`, `Unmapped::{BlockSplit, BlocksApart, BadBlocks}`.
- Produces: `LiftoverOptions { chrom_style, skip_invalid, ignore_blocks }`.

The block path, for a record with 12 or more columns and no `ignore_blocks`:
1. Parse the blocks with `bed12_blocks`, and thickStart and thickEnd from columns 7 and 8. A failure is `IoError::Parse` naming the line, with a hint to use `--ignore-blocks`; under `skip_invalid` the record is skipped and counted in `invalid`.
2. The mapping strand is `-` if column 6 is `-`, else `+`.
3. Take each block's pieces. Anything other than exactly 1 is `BlockSplit`.
4. All pieces must share the styled target name and the mapped strand, else `BlocksApart`.
5. Rebuild in input block order: `cs = first piece start`, `ce = last piece end`, `sizes = piece lengths`, `starts = piece start − cs`.
6. Map the thick ends (the algorithm below).
7. Check: `cs ≤ ce`, `ts ≤ te`, `cs ≤ ts`, `te ≤ ce`, and pieces ascending and not overlapping with the last ending at `ce` (this implies CrossMap's non-negative starts). A failure is `BadBlocks`.
8. Write columns 1–3, 7, 8, 10, 11 and 12. Write 11 and 12 comma-joined with no trailing comma, as CrossMap does. Column 6 is written as in R5. Columns 4, 5, 9 and 13+ are kept byte for byte.

Thick ends: the signature does not determine this algorithm, so here it is. `pieces[i]` belongs to block i; `src`/`tgt` are its source and target intervals.
```
start_block(p) = first i with src.start <= p < src.end, else first i with p == src.end
end_block(p)   = first i with src.start <  p <= src.end, else first i with p == src.start
fwd(i, p)      = tgt.start + (p - src.start)
mirror(i, p)   = tgt.end   - (p - src.start)
forward pieces: ts' = fwd(start_block(ts), ts);   te' = fwd(end_block(te), te)
reverse pieces: ts' = mirror(end_block(te), te);  te' = mirror(start_block(ts), ts)
either one not found (the position lies in no piece):
                ts' = cs + (ts - chromStart);      te' = ce - (chromEnd - te)    // CrossMap's offsets
```
